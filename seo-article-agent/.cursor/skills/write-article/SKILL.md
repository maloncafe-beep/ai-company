# SEO記事作成スキル

チャットの対話だけでSEO記事を完成させるスキル。
キーワード選定 → 構成案 → 本文生成 → Googleドキュメント出力 → スプシに記録まで一気通貫。

## ワークフロー

### Step 1: ジャンル・テーマのヒアリング

スキル発動したら、まずユーザーに聞く:

```text
どんなジャンル・テーマの記事を書きますか？

例:
- 「SEO対策について」
- 「整体院の集客」
- 「プログラミング学習」

ざっくりでOKです。
```

### Step 2: キーワード候補の提案

ユーザーのジャンルを元に、WebSearch で関連キーワードを調べ、**5つ程度のキーワード候補を提案**する。

検索例:
- 「{ジャンル} SEOキーワード 検索ボリューム」
- 「{ジャンル} ブログ 記事ネタ」

提案フォーマット:

```text
「{ジャンル}」関連のキーワード候補です:

① 「{KW1}」— {なぜこのKWがいいか、1行で}
② 「{KW2}」— {なぜこのKWがいいか、1行で}
③ 「{KW3}」— {なぜこのKWがいいか、1行で}
④ 「{KW4}」— {なぜこのKWがいいか、1行で}
⑤ 「{KW5}」— {なぜこのKWがいいか、1行で}

どれにしますか？番号で選ぶか、別のキーワードを教えてください。
```

ユーザーが「このキーワードで」と直接指定してきた場合は、提案をスキップしてそのまま Step 3 へ。

### Step 3: 文体・トーンの確認

キーワードが決まったら、記事の書き方を聞く:

```text
記事の文体はどうしますか？

例:
- 「ですます調で丁寧に」
- 「カジュアルに、友達に話すような感じ」
- 「専門的に、プロ向けで」
- 「前回と同じで」

ひとことで大丈夫です。
```

ユーザーの回答を、以下の記事生成ルールとして記憶する:
- 語尾スタイル（ですます / だ・である / カジュアル）
- トーン（丁寧 / フランク / 専門的）
- 特別な指示があればそれも

### Step 4: 構成案の作成・提示

キーワードと文体を踏まえ、**構成案（見出し）** を作成してチャットに提示する。

```text
「{キーワード}」の構成案です:

■ title案: {60文字以内のSEOタイトル}

---

## {見出し1}
  ### {小見出し1-1}
  ### {小見出し1-2}

## {見出し2}
  ### {小見出し2-1}
  ### {小見出し2-2}
  ### {小見出し2-3}

## {見出し3}
  ...

## まとめ

---

この構成でよければ「OK」と言ってください。
修正したい箇所があれば教えてください。
```

#### 構成案の品質基準

- H2 は 3〜6 個
- H3 は各 H2 に 2〜4 個
- 見出しにキーワードまたは関連語を自然に含める
- 検索意図を網羅する（情報型なら What/Why/How をカバー）
- 競合記事に負けない網羅性を意識する

ユーザーが修正指示を出したら、修正して再提示する。
「OK」「いいよ」「進めて」等の承認を受けてから Step 5 に進む。

### Step 5: 本文の生成

承認された構成案に沿って、本文を Markdown 形式で生成する。

#### 本文の品質基準

- **文字数**: 4,000〜6,000字目安
- **リード文**: 200〜300字。読者の悩み・疑問に寄り添い、この記事で解決できることを伝える
- **各セクション**: 見出しごとに十分な情報量。薄い段落を量産しない
- **まとめ**: 要点を箇条書き + CTA（次のアクションの提案）
- **キーワード**: 本文中に自然な頻度で含める（詰め込みすぎない）
- **文体**: Step 3 で確認したトーン・語尾を厳守する

#### 絶対やらないこと

- 「〜について解説します」「〜を詳しく見ていきましょう」等の冗長な前置き
- 同じ内容を言い方を変えて繰り返す（文字数稼ぎ）
- 根拠のない断定（「絶対に効果があります」等）
- AIっぽい定型表現（「〜という観点で」「〜は非常に重要です」）

### Step 6: Google ドキュメントに出力

本文が確定したら、Google ドキュメントに出力する。

```bash
node --input-type=module -e "
import { createArticleDoc } from './tools/lib/docs.mjs';
const title = 'ここにtitle';
const body = \`ここに本文（Markdown）\`;
const { url } = await createArticleDoc(title, body);
console.log('URL: ' + url);
"
```

### Step 7: スプシに記録

Google ドキュメントの URL をスプシの記事ログに追記する。

```bash
node --input-type=module -e "
import { appendArticleLog } from './tools/lib/sheets.mjs';
await appendArticleLog({
  keyword: 'キーワード',
  title: 'SEOタイトル',
  articleUrl: 'https://docs.google.com/document/d/xxxx/edit',
  charCount: 5200,
});
console.log('✓ スプシに記録完了');
"
```

完了後、ユーザーに結果を伝える:

```text
✓ 記事を作成しました！

■ キーワード: {keyword}
■ title: {title}
■ 文字数: {charCount}字
■ Google ドキュメント: {url}

記事の内容はGoogle ドキュメントで確認・編集できます。
続けて別の記事を書きますか？
```

## 基本姿勢

- **対話ファースト**: スプシを見に行く前に、まずユーザーと話す
- **提案してから聞く**: 「キーワードは？」ではなく「こんなのはどうですか？」
- **構成案を必ず挟む**: いきなり本文を書かない。構成案で合意を取る
- **量より質**: 文字数は目安。中身が薄い文字数稼ぎは絶対にしない
- **1回で1記事**: 記事が完成してから次の記事に進む
