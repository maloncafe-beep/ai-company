# note市場リサーチ（第2層）

テーマの**中身**は [research-topic](../research-topic/SKILL.md)（第1層）。
本スキルは**需要・競合・価格帯**（書く前の A→B）を調べる。

## 全体フローでの位置

```
ideas/idea-pool.md → 【本スキル A+B】 → research-topic（第1層） → write-note-article → 公開 → analyze-note-account（C）
```

## ワークフロー

### Step 0: コンテキスト読み込み
- `config/company-philosophy.md` — Maloncafeの軸（AI・哲学・起業・Well-being）
- `ideas/idea-pool.md` — 対象アイデア番号（あれば）
- 既存の `research/YYYYMMDD-*.md` — あれば追記、なければ新規

### Step 1: キーワード候補の確定（3〜5語）
ユーザー指定がなければ、以下の起点から選ぶ:
- AI・エージェント / Cursor / タスク管理
- 哲学 / Well-being / 価値提供
- 起業 / スタートアップ / マネタイズ / note有料化

### Step 2-A: note内検索（最優先）
WebSearch または WebFetch で `site:note.com キーワード` 相当の情報を収集し、各キーワードについて記録:

| 観点 | 記録内容 |
|------|----------|
| 記事数感 | 多すぎ＝飽和 / 少なすぎ＝需要不明 |
| 有料記事 | 件数感・価格帯（300/500/980/2980円など） |
| タイトルパターン | 「完全ガイド」「5つのコツ」等 |
| マガジン・ハッシュタグ | 有無 |

**注意**: 競合のスキ数は水増しがありうる。**絶対数より切り口・構成・価格帯**の参考に留める。

### Step 2-B: 外部SEO（Google流入を狙う場合）
WebSearch で以下を調べる（無料優先）:
- [ラッコキーワード](https://rakkokeyword.com/) 相当のサジェスト・関連語（検索結果から拾う）
- ロングテール3語以上（例: `note 有料化 始め方 初心者`）
- 月間検索ボリュームの目安（あれば）

有料ツール（noteInsight 等）はユーザーが契約している場合のみ言及。未契約なら「手動で代替できる項目」だけ埋める。

### Step 3: 競合サンプリング（上位5〜10記事）
各記事についてメモ:
- タイトル・文字数感・見出し構成
- スキ・コメント（参考程度）
- 有料/無料・価格・ペイウォール位置
- 「ぶった切り」「体験談」の有無

### Step 4: 自アカウント指標（データがあれば）
ユーザーがダッシュボード数値・CSV・スクショを渡した場合のみ:
- 同テーマ or 近いテーマの過去記事 PV / スキ / 公開日数
- **スキ率** = スキ ÷ PV × 100（10%超＝構成優秀の目安）
- **1日あたりPV** = PV ÷ 公開日数（ストック型判定）

データがない場合はセクションに「未入力（公開後に analyze-note-account で更新）」と書く。

### Step 5: 有料化判断
| シグナル | 判断 |
|----------|------|
| スキ率10%超 + コメントあり | 有料化候補 |
| ストック型（1日PV安定） | シリーズ or マガジン化 |
| 初速のみ・スキ率低い | タイトル/構成改善を先に |
| 競合同テーマが500円帯多数 | 哲学・体験で差別化必須 |

### Step 6: 保存
- 新規: `research/YYYYMMDD-テーマ名.md`
- 既存メモがある: 市場系セクションのみ追記・更新
- フロントマターに `market_research: true` と `date` を付与

第1層（概要・哲学接続等）は research-topic が担当。本スキル単独実行時は**市場系セクション＋切り口候補**まで。続けて第1層を依頼するか、ユーザーに確認する。

## 追記するセクション（必須）

`research/_market-sections-template.md` の見出し構成に従う。

## 完了時の出力

1. 保存したファイルパス
2. **おすすめキーワード1つ**（飽和度と哲学との両立理由）
3. **次のアクション**: 「第1層リサーチ（research-topic）に進む」か「執筆に進む」か

## 補足ルール

- ファクトと推測を分ける（「記事数が多い」は観察、「需要が高い」は推測ならそう明記）
- 出典URLを必ず残す
- noteにログインできない前提で、公開情報とWeb検索で代替する
