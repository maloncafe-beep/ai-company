# LP-GPT

商品情報を、公開可能なスマホ向けLPへ変換する。戦略とコピーを先に固め、ビジュアルと機能を後から実装する。

## Privacy Boundary

- 現在のワークスペースと、ユーザーが明示的に指定したファイルだけを使う。
- 他案件のフォルダ、ホームディレクトリ、ダウンロードフォルダを素材探しのために探索しない。
- APIキー、パスワード、Cookie、個人用トークンを質問したり、成果物へ保存したりしない。
- LINE、R2、社内Webhook、分析タグ、外部送信処理を自動追加しない。
- デプロイ、アップロード、公開URL作成、外部フォームへの接続は、ユーザーが明示的に依頼した場合だけ行う。
- 既存の顧客データ、生成物、参考画像を、別案件へ無断で再利用しない。

## Workflow

### 1. Establish the Project

ユーザーの現在の作業フォルダ内に、他案件と衝突しないプロジェクトディレクトリを作る。指定がなければ `lp-gpt-output/<slug>-<timestamp>/` を使う。

標準成果物を次の形にする。

```text
<project>/
├── brief.md
├── copy.md
├── index.html
├── assets/
├── screenshots/
└── build-log.md
```

既存プロジェクトを改修する場合は、その構造を優先し、不要な新規ディレクトリを増やさない。

### 2. Normalize Inputs

新規案件では `references/project-brief-template.md` を読み、以下をユーザーの情報から埋める。

- LPの目的と主CTA
- ターゲットと現状の悩み
- 商品、サービス、イベントの内容
- 提供価値、ベネフィット、差別化
- 実績、証拠、プロフィール、注意事項
- 価格、日時、場所、申込条件
- 参考デザイン、ブランドカラー、素材
- CTA、動画、フォーム、SNSなどのURL
- 必須表記と避ける表現

制作に不可欠な情報が欠けている場合だけ、一度にまとめて短く確認する。URLや補足情報など後から差し替えられる項目は、作業を止めず `未設定` として進める。

添付画像や資料がある場合は、ユーザーが今回の案件用として渡したものだけを確認する。出典不明の実績、推薦、数値、資格、効果を創作しない。

### 3. Fix the Offer and Structure

`brief.md` を作り、目的、対象、オファー、CTA、制約を固定する。曖昧な部分は推測と確定事項を分けて記載する。

5〜9セクションを目安にLP構成を設計する。通常は次の順序を基準にするが、案件に合わせて入れ替える。

1. ファーストビューと主CTA
2. 課題への共感または問題提起
3. 解決策と提供価値
4. ベネフィット、内容、特徴
5. 実績、証拠、信頼材料
6. 利用の流れ、日程、料金
7. FAQまたは不安の解消
8. 最終CTAと注意事項

ユーザーの事実だけを使って `copy.md` を作る。未確認の主張には `[要確認]`、リンク未設定には `[URL未設定]` を付ける。

### 4. Choose the Production Mode

ビジュアル制作に入る前に、次の基準で方式を決める。

- 参考画像があり、ビジュアルの再現性を優先する: ハイブリッド画像スライス方式。
- 日本語の正確さ、編集性、SEO、レスポンシブ性を優先する: HTMLテキスト方式。
- 画像生成機能が利用できない: HTML/CSSを中心に完成させ、画像生成だけを未実施として記録する。
- 既存の画像スライスがある: 画像を再生成せず、HTML化工程から始める。

ハイブリッド画像スライス方式または既存画像のHTML化では、兄弟スキル `../image2-mobile-lp-builder/SKILL.md` を読み、そのワークフローとQAを使う。

日本語の重要な文章をAI生成画像内だけに閉じ込めない。正確な見出し、価格、日時、CTA、注意事項はHTMLテキストとして保持する。

### 5. Build the LP

- スマホを最優先にし、390pxと430pxで破綻しないレイアウトにする。
- PCでは最大430px程度のLPキャンバスを中央表示する。
- CTA、動画、フォーム、リンクを実際に操作できるHTML要素にする。
- URLが未設定なら、外部サイトへ送らず、差し替え箇所が分かる仮モーダルを使う。
- 画像、CSS、JavaScriptをプロジェクト内へ保存し、個人環境の絶対パスを参照しない。
- CDNや外部フォントを必須依存にしない。使用する場合はユーザーの要件と利用条件を確認する。
- 機密情報や認証情報をクライアント側HTMLへ埋め込まない。

### 6. Verify

兄弟スキルを使った場合は `../image2-mobile-lp-builder/references/qa-checklist.md` を読む。

最低限、次を確認する。

- 390pxと430pxで横スクロールが出ない。
- PCでLPが中央表示される。
- 主CTAが最初の画面で理解できる。
- すべてのボタン、リンク、モーダルが動く。
- Esc、背景クリック、閉じるボタンでモーダルを閉じられる。
- 未設定URLと `[要確認]` が納品時に一覧化されている。
- 個人の絶対パス、トークン、外部通知先が成果物に入っていない。
- スクリーンショットを生成し、目視確認している。

検証結果と残課題を `build-log.md` に記録する。

### 7. Deliver

完成ファイルのパス、実装したCTA、未設定項目、検証結果を簡潔に報告する。ユーザーが公開を依頼していない場合は、ローカル成果物の提示で止める。
