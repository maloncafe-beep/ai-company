# 🔍 案件探索＋スプシ登録 手順書 — 担当：リサ

複数の案件サイトを横断検索して案件を一覧化し、スプレッドシート「1_案件検索」に登録する。

**スプシURL**: `https://docs.google.com/spreadsheets/d/1xa9cVV28mP53P2Vyq2UtTP9piRr5-r_niaPQ2ZiLsNQ/edit?gid=753704806#gid=753704806`（maloncafe@gmail.com）

## ✅ 現在の実働手順：WebSearch版（T40 実証済み）

> **これが今使える方法。毎回この手順で動く。迷ったらここから始める。**

### ⚠️ ツール使用ルール（最重要・必ず守る）

| ツール | 用途 | 使ってよいか |
|--------|------|-------------|
| **WebSearch** | 案件の一覧検索・キーワード検索 | ✅ **最初に使う。メインツール** |
| **WebFetch** | 個別案件の詳細確認（数件のみ） | ⚠️ パフォーマンスが悪いため最小限（一覧検索には使わない） |
| **Claude-in-Chrome** | ブラウザ操作全般 | ❌ **禁止**（承認クリックが頻発して社長の手間になる） |

### STEP 1：WebSearch で案件を一括検索

**ランサーズ（LC）** — 以下のようなクエリで検索する：

```
site:lancers.jp/work/detail 記事作成 募集中
site:lancers.jp/work/detail 文書作成 AI使用可
site:lancers.jp/work/detail ブログ作成 継続
site:lancers.jp/work/detail 資料作成 提案書
site:lancers.jp/work/detail ライティング トライアル
```

**CrowdWorks（CW）** — 以下のようなクエリで検索する：

```
site:crowdworks.jp/public/jobs 記事作成 募集
site:crowdworks.jp/public/jobs 文書作成 AI
site:crowdworks.jp/public/jobs ブログ記事 継続
site:crowdworks.jp/public/jobs 資料作成 提案書
site:crowdworks.jp/public/jobs ライティング トライアル
```

> ✅ WebSearch はキーワードを変えながら複数回実行してよい。各回でURLと案件タイトルを収集する。
> ⚠️ 個別案件URL（`/work/detail/XXXXXXX` または `/public/jobs/XXXXXXX`）が確認できた案件だけを記録。
> 検索結果ページのURLを個別案件URLとして使い回すことは絶対にしない。

### STEP 2：候補を絞り込み、日付不明案件だけWebFetchで確認

1. WebSearch の結果からタイトル・報酬・競合数で候補を絞り込む
2. 絞り込んだ候補の中で **納期/期限が不明な案件のみ** WebFetch で個別URLを確認して日付を取得する
3. 日付が本日（検索実施日）より前、または「募集終了」「契約済み」が確認できたら除外する

```
WebFetch で個別案件URL（例：https://crowdworks.jp/public/jobs/12345678）を取得
確認項目：納期/期限 / 募集状況（終了していないか） / 報酬 / 提案数 / 依頼内容
```

> ✅ WebFetch は「絞り込み後・日付不明案件の確認」に限定すれば許容範囲。
> ⚠️ 一覧ページへの適用・大量件数への適用は禁止（パフォーマンスが悪い）。

### STEP 3：ローカルCSVに書き込む（スプシ直接入力は使わない）

> ⚠️ **ブラウザでのセル直接入力・タブキー入力は使わない。列ズレが起きる。**
> **必ずCSV中間ファイル経由でスプシに登録する。**

**書き込み先ファイル：** `logs/案件検索結果.csv`

このファイルに案件を追記する（Write ツールで末尾に行を追加）。

**列順（CSV・スプシ共通）：**

| 列 | 内容 | 例 |
|---|---|---|
| A | 管理ID | `5574847`（URLの末尾の数字） |
| B | 媒体 | `ＬＣ`（ランサーズ）/ `ＣＷ`（CrowdWorks） |
| C | 案件タイトル | タイトルそのまま |
| D | 報酬（単価） | `1万〜2万円` |
| E | クライアント名 | 不明なら「不明」 |
| F | 納期/期間 | `2026/07/22`（YYYY/MM/DD形式・必ず絶対日付。「あと○日」禁止） |
| G | 案件URL | `https://www.lancers.jp/work/detail/5574847` |
| H | メモ・ステータス | 提案数・特記事項など |
| I | 検討 | 空欄（社長が記入） |
| J | 仕事の詳細 | 空欄 |

> ⚠️ **カンマ除去ルール（必須）**：列は10列固定のため、フィールド値に桁区切りカンマが入ると列ズレが起きる。
> 書き込み前にすべてのフィールド値から桁区切りカンマを除去する。
> 例：`9,000円` → `9000円`、`10,000円` → `10000円`、`6,000円/本` → `6000円/本`

**メリット：**
- 途中で止まっても CSV に書いた分は残る → 再開できる
- ブラウザ操作不要 → 列ズレしない

### STEP 4：CSVをスプシに同期（確認後実行）

CSV書き込み直後に以下を実行する（CSV件数を表示し、社長の確認後実行）：

```bash
node server/scripts/sync-sheet.mjs
```

- 管理ID（A列）で重複チェックし、新規行だけを追記する。
- 同期完了をもってタスク完了とし、社長に件数とスプシURLを報告する。

### 除外する案件

- 提案数100件超
- 個別URLが取得できない
- マスター社長の強み（AI活用・業務効率化・提案書・IT中小企業向け）と無関係
- **「募集終了」「締切済」「契約済み」がWebSearchの結果文中に確認できたもの**
- ※ WebSearchのみでは期限切れの事前排除は不可能。期限確認は社長がURLを開いて判断する
- タイトルに年齢制限の記載があるもの（例：「年齢20代」）

### 重複チェック

- 案件ID（URLの末尾の数字）が既存行と被っていないかスプシを見て確認
- 同一タイトルもスキップ

## 📦 Node.js スクリプト（`server/scripts/` で実行）

キーワード管理はスプシの「キーワード設定」シートで一元管理。以下のスクリプトで操作する。

```bash
node server/scripts/read-keywords.mjs   # スプシからキーワードを取得してJSON出力
node server/scripts/sync-sheet.mjs      # logs/案件検索結果.csv をスプシに同期
```

キーワード設定シートの列構成：A=カテゴリ / B=キーワード / C=除外条件 / D=有効（✓）

## 納品ルール

- 探索結果の要約（おすすめ順・理由付き）を `logs/` に Markdown 保存する。ファイル名規則はyyyymmdd_[Txx:タスク番号]_要約.md
- スプシURLを報告に含める（秘書アイが `deliverables.url` に入れる）。
- 有望案件が見つかったら「コトハに応募文を書かせる」流れを次のおすすめとして添える。
