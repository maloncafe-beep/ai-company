# 案件応募の手順フロー — 秘書アイの運用ガイド

**対応プラットフォーム：クラウドワークス・ランサーズ・その他案件サイト（汎用）**

秘書アイ（案件管理）が案件受け取りから納品まで、確実に進める手順書。
各プラットフォームの細部の違いは無視し、共通の応募・進行・納品フローを統一。

---

## 📁 ファイル管理の原則

**すべての案件は、案件番号ごとにフォルダを作成して管理する。**

```
保存先：logs/案件/[案件番号]/

例：
logs/案件/CW62890601/
├── CW62890601応募文_20260807.md
├── CW62890601進捗ログ.md
├── CW62890601納品物.md
└── 修正・フィードバック記録.md

ランサーズの場合：
logs/案件/LC5578274/
├── LC5578274応募文_20260807.md
├── ...
```

**ルール：**
- ファイル名に案件番号を含める → 社長が検索しやすい
- yyyymmdd で日付を入れる → どの版か分かる
- すべてのやり取り・修正・納品物を同じフォルダに → 案件の全履歴が一箇所に

## フェーズ1：案件選定（秘書アイ責務）

### STEP 1. 案件情報の整理
案件を受け取ったら、以下の情報を整理：

```
案件ID        : [案件番号]
案件名        : [タイトル]
ジャンル      : [分類]
予算          : [金額]
納期          : [期限]
難易度        : [低/中/高]
マスター社長OK: [YES/NO]
```

### STEP 2. 応募可否の判定

**以下の場合は応募しない ❌**
- 予算が極端に低い（相場の50%未満）
- 納期が極端に短い（工数に対して非現実的）
- 外部ツール（LINE等）でのやり取り強要
- 無料モニター・無報酬案件
- 個人情報の不自然な要求
- 転売・グレーな内容

**応募OKなら → STEP 3 へ**

### STEP 3. マスター社長への報告と判断

```
【案件紹介】
■案件名：[タイトル]
■ジャンル：[分類]
■予算：[金額]（マーケット相場比：○%）
■納期：[期限]（工数余裕度：○%）
■ポイント：[なぜこの案件が良いのか]

応募しますか？
1. OK、応募する
2. 応募をやめる
3. もっと情報が欲しい
```

社長の OK を待つ（勝手に応募しない ❌）

## フェーズ2：応募文作成（コトハ責務）

### STEP 4. 募集要項の徹底確認（秘書アイ責務・最重要）

**秘書アイが実行する（コトハではなく秘書アイ自身）**

#### 4-1. 「ご応募時に記載すべき内容」指示を最後まで読む（最優先）

CW・ランサーズのページ内に**「ご応募時に、以下の内容をご記載ください」**という指示がある場合、それを最後まで読む。

例：
- 「簡単な自己紹介、好きな作品、ライティング経験」と指定されている
- 「ポートフォリオ」「稼働時間」「単価希望」などの指定がある

**この指示がテンプレートより優先される。**

#### 4-2. 募集要項の全体像を確認

```
【募集要項チェック】
□ 作業内容：何を作るのか
□ 納品形式：どんな形式で？
□ 品質基準：何を基準に判定？
□ クライアント要望：参考資料・具体例あるか
□ 修正回数：何回まで対応可？
□ 稼働時間：どのくらい必要か
□ 「ご応募時に記載すべき内容」指示：何を書くべきか

【クライアント情報確認】
□ 過去評価：★いくつ？
□ 支払い実績：きちんと払ってる？
□ 他の案件：評判は？
```

#### 4-3. コトハへの具体的な指示を作成

応募要項の指示を踏まえて、コトハに：
- 「クライアント側は◇◇という指示をしているので、この内容を含めて作成」
- 「テンプレート①参考だが、指示に合わせてカスタマイズ」
という形で指示を出す。

### STEP 5. コトハによる応募文作成

コトハがテンプレートを使用：
→ `tools/job-application/応募文テンプレート集.md` 参照

**必ず以下を網羅：**
1. 冒頭の挨拶（本名フルネーム）
2. 募集要項への具体的言及（「〇〇という部分について、以下の対応が可能です」）
3. 具体的な実績・数値（「過去20件・平均評価4.8」）
4. 作業プロセス・スケジュール明示（「1日目：ラフ案作成、2日目：修正」）
5. 付加価値の提案（「通常の納品に加えて△△も対応可能」）
6. 稼働時間・連絡頻度（「24時間以内のレスポンス」）
7. 最後の意欲表明（「全力で取り組みます」）

### STEP 6. 応募文の保存

コトハが応募文を完成させたら、以下に保存：

```
保存先：logs/案件/[案件番号]/
ファイル名：[案件番号]応募文_yyyymmdd.md

例：CW62890601応募文_20260807.md
```

秘書アイから社長へ：
```
【応募文完成・保存完了】
案件名：[タイトル]
予算：[金額]

応募文ができました。以下に保存しました：
📄 logs/案件/[案件番号]/[案件番号]応募文_yyyymmdd.md

ご確認いただいて、修正指示やフィードバックをください。
```

## フェーズ3：応募前の最終確認～応募実行

### STEP 7. 社長による確認・修正

社長が応募文をレビューし、以下のいずれかを指示：

1. **「OK、これで送信して」**
   → STEP 8 へ
2. **「ここを修正して：◇◇」**
   → コトハが修正 → STEP 6 に戻る
3. **「応募をやめる」**
   → 案件終了

### STEP 8. 応募実行（社長確認後のみ）

社長の「送信OK」を受けて、秘書アイが確認してから CW・ランサーズ上で**手動で**応募を実行：

```
応募前の再確認：
□ 案件番号：[◇◇]
□ 応募文ファイル名：[yyyymmdd版であることを確認]
□ 社長 OK をもらったか：YES
□ クライアント・予算・納期に問題ないか：YES
```

**社長の承認なしに応募ボタンを押さない** ❌❌❌

### STEP 9. 返信待ち

CW・ランサーズ上でクライアント返信を待つ。

## フェーズ4：案件開始準備（キックオフ）

### STEP 9. クライアント返信が来た場合の対応

```
【キックオフ確認項目】
□ 要件の詳細確認：何を作るのか、どんな品質で
□ 参考資料・イメージ：クライアント側の参考例
□ スケジュール：工程別の期限・修正期間
□ 連絡方法：CW 内メッセージが基本（外部ツールは確認）
□ 修正対応：何回まで対応するのか
□ ファイル形式：納品形式の確認
```

秘書アイから社長へ：
```
案件開始にあたり、クライアントに以下を確認しました：
[内容]

問題がなければ、コトハに作業開始を指示します。
OK ですか？
```

### STEP 10. 作業開始指示

社長 OK 後、コトハに作業タスクを起票し、着手。

---

## フェーズ5：進行管理（社長・コトハ・秘書アイ）

### STEP 11. 進捗報告と品質確認

**コトハが日単位で報告：**
→ `tools/job-application/進捗報告テンプレート.md` 参照

**秘書アイが中間確認**（30%・60%・90%時点）

---

## フェーズ6：納品

### STEP 12. 最終チェック（秘書アイ＆コトハ）

```
【納品前チェックリスト】
□ 要件すべて網羅されているか
□ ファイル形式は正しいか
□ ファイル名は指定通りか
□ 誤字脱字・リンク切れはないか
□ 動作確認は済んでいるか（各環境で）
□ マニュアル類は揃っているか
□ バックアップは取ったか
```

### STEP 13. 納品実行

秘書アイから社長：
```
最終チェック完了。以下で納品します：

【納品物】
・xxxx（メイン成果物）
・マニュアル
・その他補足資料

送信してOKですか？
1. 送信する
2. 修正指示がある
3. もう一度確認したい
```

社長 OK 後、CW 上で納品。

### STEP 14. クライアント確認～完了

クライアント確認待ち → 完了確認。

修正指示が来た場合は → STEP 11 に戻る

---

## フェーズ7：アフターフォロー

### STEP 15. 高評価獲得後

秘書アイから社長：
```
【高評価獲得】
案件：[タイトル]
クライアント評価：★5
報酬：確定

次のステップ：
1. アフターフォローメッセージを送る
2. 次の案件がないか打診する
3. 単価交渉を検討する
```

→ `tools/job-application/進捗報告テンプレート.md` の「アフターフォロー例」を参照

## 🔐 秘書アイが絶対に守るルール

| これはダメ ❌ | 正しい流れ ✅ |
|---|---|
| 案件を見つけて勝手に応募 | 案件情報 → 社長報告 → 社長 OK → 応募 |
| 応募文を勝手に送信 | コトハが作成 → 秘書アイが確認 → 社長 OK → 送信 |
| クライアント返信を無視 | キックオフ内容を整理 → 社長報告 → 社長確認 → 作業開始 |
| 納品を勝手に進める | 最終チェック完了 → 社長報告 → 社長 OK → 納品 |
