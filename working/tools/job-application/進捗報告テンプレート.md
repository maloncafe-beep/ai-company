# 案件進行管理 — 進捗報告・相談テンプレート（汎用）

**対応プラットフォーム：クラウドワークス・ランサーズ・その他案件サイト**

案件進行中、コトハが毎日社長（経由：秘書アイ）に報告する際のテンプレート。
プラットフォーム問わず、報告の形式・内容は共通で使用可能。

---

## 【日次進捗報告】 — 毎日夜に報告

```
【案件進捗報告】— [案件名] —

■本日の作業内容
・[具体的な作業 1]
・[具体的な作業 2]
・[具体的な作業 3]

■進捗状況
全体の [◇]% 完了しています。

■明日の予定
・[明日の予定 1]
・[明日の予定 2]

■その他（問題なければ不要）
特に問題はございません。

何かご確認いただきたい点がございましたら、お気軽にご連絡ください。
```

**ルール：**
- 夜 20:00 以降に報告（社長が確認しやすい時間）
- 作業内容は**具体的に**（「設計中」ではなく「ログイン画面のワイヤーフレーム作成完了」）
- 進捗は%で必ず示す
- 問題がなければ簡潔に（3～4行で OK）

---

## 【中間確認リクエスト】 — 30%, 60%, 90% 時点

```
【中間確認のお願い】— [案件名] —

お疲れさまです。進捗が [◇]% に達しましたので、以下の点についてご確認をお願いいたします。

■現在の成果物（確認例）
1. デザイン案：[▼] ← クリックで確認可能にしておく
   → [具体的な説明：「ヘッダー・メインビジュアル・フッター完成」など]

2. 構成・方針：[▼]
   → [「このアプローチで進めても問題ないか」という確認ポイント]

■確認していただきたい点
1. 方向性は正しいか？ A.OK ／ B.修正希望
2. デザイン案は気に入っていただけるか？ A.OK ／ B.別案希望
3. 納期予定（[◇日目納品]）に問題ないか？ A.OK ／ B.調整希望

ご指摘いただければ、すぐに対応させていただきます。
ご確認をお願いいたします。
```

**ルール：**
- 30% 時点：「方向性合意」が目的（選択肢で答えやすく）
- 60% 時点：「内容確認＋修正フィード」（返信に必要な情報を絞る）
- 90% 時点：「最終確認＋修正依頼」

## 【問題発生時の相談】

```
【相談：〇〇について】— [案件名] —

お世話になっております。
作業進行中に [問題内容] が発生しましたので、ご相談させていただきます。

■現状の問題点
[問題を簡潔に説明]

例：
・クライアント指定の「〇〇フォント」がシステムに入っていない
・スケジュール：初回案を [◇日] に提出予定だったが、修正要望が [◇点] 出た
・技術的な制約：[◇]という要件が実装困難

■考えられる対応案
案1：[対応 1]
  → メリット：[〇〇]、デメリット：[〇〇]

案2：[対応 2]
  → メリット：[〇〇]、デメリット：[〇〇]

案3：[対応 3]
  → メリット：[〇〇]、デメリット：[〇〇]

上記 3 案のうち、どちらが望ましいでしょうか？
または別のご提案があればお教えください。

ご指示をお待ちしております。
```

**ルール：**
- 問題は「単なる報告」ではなく、自分で 2～3 案を考えてから相談
- クライアントには直接言わない（社長 → 秘書アイ経由で判断）
- 納期に影響する問題は特に早めに報告（朝一番で）

## 【修正指示の確認】 — 修正依頼が来た時

```
【修正内容の確認】— [案件名] —

ご指摘ありがとうございます。
修正内容について、以下の点を確認させていただけますでしょうか？

■修正要望 1：[大まかな指摘]
→ 具体的には、以下のどちらでしょうか？
  A. [パターン A]
  B. [パターン B]
  
または、参考になるデザイン・事例があればお教えください。

■修正要望 2：[別の指摘]
→ 現在の [〇〇] から [△△] に変更すればよろしいでしょうか？

■スケジュール
修正対応に [◇日] いただき、[◇日] に修正版を提出させていただく予定です。
問題ございませんか？

ご確認をお願いいたします。
```

**ルール：**
- 修正指示が曖昧なら、選択式で確認（相手の返信負担を減らす）
- 「了解しました」だけでは返信しない（確認質問を必ず添える）

## 【納品時のメッセージ】

```
【成果物納品のお知らせ】— [案件名] —

お世話になっております。
本案件の成果物が完成いたしましたので、CW上で納品いたします。

■納品物の内容
1. [メイン成果物]（形式：[◇]）
   - 内容：[〇〇ページ分、〇〇機能]

2. [補足資料]（形式：[◇]）
   - 内容：[操作ガイド、トラブルシューティング等]

■ファイル構成
- ファイル名：[構成例]
- 命名ルール：[説明]

■利用にあたっての注意事項
- [必要なツール]：[◇]ソフト最新版が必要です
- [初期設定]：[◇]の設定をお願いします
- [その他]：[〇〇の互換性について]等

■動作確認済み環境
- OS：[Windows 10, macOS 12等]
- ブラウザ：[Chrome 最新版, Safari 等]
- その他環境：[〇〇]

■今後の対応
ご確認の際に、以下の点についてご指摘いただけると幸いです：
1. ファイルは正常に開けるか
2. 基本機能は動作するか
3. デザイン・内容に問題ないか

ご不明な点やご質問がございましたら、お気軽にお聞きください。

本案件を通じて、お力になれることができれば幸いです。
よろしくお願いいたします。
```

**ルール：**
- 単に「納品しました」ではなく、何をどう使うか具体的に説明
- 問題発生時の連絡先・対応時間を明記（信頼感向上）

---

## 【アフターフォロー】 — 納品後 1 週間

```
納品から 1 週間が経ちましたが、成果物の運用に問題はございませんでしょうか？

ご不明な点や気になる部分がございましたら、お気軽にご相談ください。

特に以下の点について、ご確認いただければ幸いです：

■機能面での確認
・全ての機能が正常に動作しているか
・エラーや問題が発生していないか

■操作面での確認
・操作方法で分かりづらい点はないか
・追加で説明が必要な部分はないか

■その他
・追加で対応してほしい内容はないか
・今後のご相談があればお聞きします

※重要な連絡事項やマニュアル等は、お手元での保管をお願いいたします。
   CW のメッセージ・ファイルは、契約完了から 2 年後に削除されます。

円滑な運用のサポートをさせていただきたく存じます。
```

## 【高評価獲得時】 — 次の案件につなげる

```
このたびは業務をご依頼いただき、誠にありがとうございました。
高い評価をいただき、大変嬉しく思います。

今回の制作を通じて、貴社の [事業内容・ターゲット層] についての理解が深まりました。

以下のような内容であれば、今後もお力になれると考えております：
- [提案 1：次に対応可能な内容]
- [提案 2：別のジャンルで対応可能な内容]
- [提案 3：継続対応できる内容]

機会がございましたら、ぜひお声がけいただけますと幸いです。

本当にありがとうございました。
```

**ルール：**
- 評価が ★4 以上なら、この連絡を送る
- 次の案件の提案は「押し付けにならないように」（相手が検討しやすい形で）
- リピート案件に繋がれば、単価交渉への足がかりになる

## 【単価交渉】 — 実績を積んだ後

```
○○様

いつもお世話になっております。
先日納品させていただいた案件について、ご確認いただきありがとうございました。

これまで [◇ヶ月間] 、貴社の案件に携わらせていただき、以下のような成果を上げることができました：

■実績
- 成果物 [◇] 件の納品（平均評価 ★[◇]）
- [具体的な成果：「サイトのPV が 30% 増加」等]
- [クライアント満足度：「修正なし納品 [◇] 件」等]

この間、[新しいスキル・資格] を取得し、より質の高い提案・対応ができるようになりました。

そのため、今後の案件につきまして、単価の見直しをご相談させていただきたく存じます。

**現在の単価】¥[◇] → 【ご提案単価】¥[◇]

【ご提案の理由】
- 提供品質の向上
- 納期・修正対応の迅速化
- 追加サービス（[◇]）の実施

ご検討のほど、よろしくお願いいたします。
```

**ルール：**
- 時期：高評価 3 件目以降、または 3～6 ヶ月の継続後
- 根拠：「数値・実績」を必ず示す（感情論ではなく）
- 幅：相場 10～20% アップを目安に

## 基本的な報告ルール（秘書アイ・コトハ共通）

| これはダメ ❌ | 正しい報告 ✅ |
|---|---|
| 「進捗中です」（何をしてるか不明） | 「ログイン画面 60% 完成、明日はメイン画面に着手」 |
| 「問題が出ました」（何が問題か不明） | 「〇〇という要件が実装困難。対応案は 2 つあります」 |
| 「修正しました」（何を修正したか不明） | 「色をA→Bに変更、フォントサイズ16→18に変更」 |
| 「納品したので確認してください」 | 「[内容説明]を納品しました。以下の点をご確認ください→[項目]」 |
