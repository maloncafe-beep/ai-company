# Codex × YouTube台本量産 並走エージェント

このフォルダはクラウドワークス・ランサーズ等で受注した
YouTube台本案件をクライアント単位で管理・量産するための作業ディレクトリ。
Codex は以下のルールで動くこと。

## 担当タスク
- profile.md             : 視聴傾向・ライティング経験・稼働時間・希望単価をまとめる
- clients/{client-name}/ : クライアント単位のフォルダ。受注時に Codex が作成
  - AGENTS.md            : クライアント前提・トーン・禁則事項・お決まりフレーズ
  - references/          : 参考動画の文字起こし＆要約（{video-id}.txt 形式）
  - scripts/             : 納品台本（{YYYY-MM-DD}_{タイトル}.md 形式で保存）
  - style-guide.md       : 参考動画から抽出した文体・構成パターン
  - state.md             : 案件状態・進捗管理
- reports/{YYYY-MM}/     : 月次のテーマ提案・視聴維持率レポート・リスク監査結果を保管

## ルール
- 出力は UTF-8、改行 LF
- 応募文・台本を生成する時は profile.md と該当 clients/ 配下を必ず参照する
- クライアントAの文体をクライアントBに混ぜない（フォルダ分離を厳守）
- 既存ファイルを上書きする前に必ず diff を見せて確認を取る

## 提案文の絶対ルール
- 自分主体の応募理由はNG（「学びたい」「経験を積みたい」禁止）、相手メリット主体で書く
- 「ご提案します」「ご相談いただけます」は使わない（応募者の謙譲語『〜できればと存じます』『お声がけいただけますと幸いです』で揃える）
- 単価が低くても実績・機能・周辺領域は削らない（価格中立で書く）
- 「最初に確認したい項目」型の質問リストはNG。進め方を具体化する
- AIで書いたかの開示はクライアント契約次第。事前に確認すること

## ユーザーが渡すプロンプト内の {波カッコ} について
- ユーザーが投げてくるプロンプト本文に `{案件名}` `{文字数}` `{client-name}` 等のプレースホルダが残っていたら、勝手に推測で埋めず、必ず確認質問を1回だけ投げ返して値を確定させること

## STEP 2-3：トライアル台本の書き方

受注 or トライアル課題が来たら、以下の順で進める。

### 手順1：クライアントフォルダを作成する（受注直後に1回）

```
新しいクライアントを受注しました。clients/{client-name}/ にプロジェクトを立ち上げてください。

【受注情報】
- クライアント名: {例: AcmeChannel}
- ジャンル: {例: 雑学}
- 動画尺・文字数: {例: 10分／5,000字}
- 単価: {例: 1本5,000円}
- 週本数: {例: 週2本}
- 参考動画URL: {3〜5本のURL}
- トーン指定: {例: ですます調}
- NGワード: {例: 断定表現NG、芸能人の実名NG}
- 納品形式: {例: Googleドキュメント}
```

→ `clients/{client-name}/` 配下に AGENTS.md・references/・scripts/・style-guide.md・state.md を自動生成する。

### 手順2：参考動画の字幕を取得して references/ に置く

```bash
# 字幕取得（参考動画1本ごとに実行）
cd ~/script-Codex/clients/{client-name}/references
yt-dlp --write-subs --write-auto-subs --sub-langs ja --skip-download --convert-subs srt "{YouTube URL}"
# .srt が落ちたらテキスト部分だけ抜いて {video-id}.txt にリネーム

# 字幕がない動画は whisper で音声から起こす
yt-dlp -x --audio-format mp3 -o "{video-id}.%(ext)s" "{YouTube URL}"
whisper "{video-id}.mp3" --language ja --model small --output_format txt
```

→ txt が揃ったら「references/ 配下の txt を全部読み込んで style-guide.md を更新して」と一言指示するだけで style-guide が再構築される。

### 手順3：台本生成パイプラインを実行する（1本90分）

```
{client-name} の台本パイプラインを起動してください。

【今回のテーマ】
- タイトル候補: {例: 「人類が知らない深海の驚異TOP5」}
- 文字数指定: {例: 5,000字}
- 動画尺: {例: 10分}
- 特殊要件: {例: 冒頭30秒で離脱を防ぐ強いフック、5分前後でフック再投入}

【実行する5モジュール】
1. リサーチ（テーマ情報収集＋事実確認、オリジナル情報3つ）
2. 構成設計（style-guide.md 参照。冒頭フック→本論→再フック→エンディング）
3. 本文生成（クライアント文体厳守、NGワード禁止）
4. ゆっくり化（必要なら。霊夢＝聞き役、魔理沙＝解説役）
5. 納品形式整形（文字数±10%以内、SE/挿絵指示を分離）

完成したら clients/{client-name}/scripts/{YYYY-MM-DD}_{タイトル}.md として保存し、納品形式版もコピペできる形式で表示してください。
```

### 手順4：納品前セルフレビュー（必ずやる）

```
{client-name} の最新台本にセルフレビューを実行してください。

【チェック項目】
1. 事実誤認（数字・年代・固有名詞）
2. 冗長チェック（3分以上同じトーンが続いていないか）
3. お決まりフレーズの整合（style-guide.md 参照）
4. NGワードチェック（AGENTS.md 参照）
5. 文字数チェック（指定±10%以内か）
6. 構成チェック（冒頭フック／再フック／エンディングCTA）

問題を箇条書きで一覧化（行番号＋問題＋修正案）。問題ゼロなら「納品OK」。
```

### 全体フロー

```
受注 → 手順1（フォルダ作成）→ 手順2（参考動画の字幕取得）
     → 手順3（台本生成）→ 手順4（セルフレビュー）→ 納品
```
