# リサーチ方法：正論と異論で題材を掘る

2026-10-05 時点の運用（直近5本のリサーチで実際にやった手順を整理したもの）。
旧方法（哲学接続・6フレームワーク）は `archive/` に移した。

## 原則
- 結論は最後。出さなくてもよい（Go/No-Goは経営者が決める）。
- 事実と仮説を分ける。一次資料まで確認できたものだけを事実とし、未確認には ★ を付ける。
- 自分が選んだ検索語・調べた範囲の偏りを、メモの冒頭に書く。

## 手順
1. **需要の確認**
   - 調査データ（出典・対象・時期・サンプル数）を集める。数字は聞き方・対象で変わるので、幅があれば幅のまま書く。
   - note内検索（人気順／急上昇）で、同じ題材の記事数・スキ上位・タイトルの傾向を見る。
2. **正論を置く**
   - 正論＝世間や note 上位記事の主流の主張。まず「何と言われているか」を一文ずつ書く。
3. **異論を探す**
   - 異論は「反対側の一次データ」から探す（例：「なりたくない」6〜8割に対し、現役管理職の95%は「なって良かった」）。
   - データがない異論は「仮説」と明記する。データあり／仮説の区別を落とさない。
4. **異論にも反論をぶつける**
   - 異論をそのまま採用しない。調査対象の偏り、質問設計、別調査との食い違いを書き、「どちらも成り立つ点」を探す。
5. **未解決を書く**
   - 原典未確認の数字、裏づけのない仮説、追加で確認すべきことを番号付きで残す。
6. **暫定の見立て**
   - 需要の有無、飽和度、空いている可能性のある位置を書く。「結論ではない」と明記する。

## 正論・異論の選び方（題材を選ぶ時の基準）
- 飽和側（共感・「逃げではない」など）は避け、**両者が食い違う点**、またはなぜ食い違うかを掘る位置を探す。
- 主流の論と、別の軸で成り立つ論を並べる（「なりたくない」理由と「良かった」理由は別の軸、など）。
- 本人が「ひっかかる」点から入り、別の観点で深掘りする（経営者の方法。個性になる）。
- 決めるのは経営者。候補は2〜3個出し、1つに絞らない。

## 保存
- `research/YYYYMMDD-theme-題材名.md`
- 実施したら LOG.md に1行追記する。
