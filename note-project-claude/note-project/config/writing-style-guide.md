# ライティングスタイルガイド

> 記事執筆時はこのスタイルを徹底的に再現する。

## 冒頭パターン

定型句は使わない。テーマに合ったつかみを毎回考える。

### パターンA: 共感型
```
（読者の状況をそのまま描写する）
「〜ということ、ありませんか？」
```

### パターンB: 未来志向型
```
「こうだったらいいと思いませんか？」
（理想の状態を先に提示して引き込む）
```

### パターンC: 問いかけ型
```
（根源的な問いを一文で投げる）
「〜って、何だろう。」
```

### パターンD: シーン描写型
```
（具体的な場面・瞬間から入る）
（2〜3文で状況を描写してから本題へ）
```

### パターンE: 断言型
```
（結論を最初に言い切る）
「〜です。断言します。」
```

※「こんにちは！ご機嫌いかがですか。」は使わない。
※「今日もAIに助けてもらっています」などのAI開示は冒頭に入れない。
※つかみの良し悪しがスキ数を左右する。定型句に逃げない。

## 文章リズムのルール

### 短文 → 短文 → 太字 のリズム
```
これ、めちゃくちゃ驚いた。

普通のAIって、言われたことをそのままやろうとするじゃないですか。
でもClaudeは「まず認識を揃えさせてください」から入ってきた。

**優秀なコンサルタントとか、できる部下がやる仕事と同じなんですよね。**
```

### 問いかけ → 即答え パターン
```
なぜ特定の人に恋をする？

顔？→もっと美人/イケメンはいる
性格？→もっと優しい人はいる
スペック？→もっと高収入はいる

でも「この人じゃなきゃダメ」になる。

なぜか？

**共有した時間と経験が代替不可能性をもたらすから。**
```

### 箇条書きの畳み掛け
```
* 「もっといいものを逃してるかも」
* この恐怖が、現代人を支配してる。
* 恋人といても、他のカップルが気になる。
* 仕事してても、他の会社が気になる。
* 何を選んでも、不安。
```

## 太字（**bold**）の使い方

記事の最大の特徴。以下の場面で使う:
- **核心メッセージ**: その段落で一番言いたいこと
- **転換点**: 「でもね、ここに一つ、重要な前提がある。」
- **結論**: 「**代替不可能だと信じること。それこそが、愛の本質だ。**」
- **独立した強調文**: 2〜3行を太字にして独立させる

## 改行・空白の使い方

- 一文ごとに改行する（スマホ最適化）
- セクション間は空行2つ
- 重要な文の前後に空行を多めに入れる
- 短い段落（1〜3文）を積み重ねる構成

## 語尾パターン集

| 場面 | 語尾例 |
|------|--------|
| カジュアル | 〜なんですよね。/ 〜なわけです。/ 〜でしょ？ |
| ツッコミ | 〜では？/ 〜なんだよな。/ 〜ですよね。笑 |
| 断言 | 〜です。断言します。/ 〜なんです。 |
| 問いかけ | 〜じゃない？/ 〜だと思いませんか？ |
| 自虐 | 〜でした。(その節はごめん。笑) |
| 感嘆 | 〜やばい。/ 〜最高じゃない？ |

## 「笑」の使い方

- 自虐の後: 「我ながら雑魚です。笑」
- ツッコミの後: 「目的がない。笑」
- 照れ隠し: 「ちょっと恥ずかしい。笑」
- テンションの表現: 「マジでヤバい。笑」
- 頻度: 1セクションに1〜2回程度

## 構成パターン（記事タイプ別）

### TYPE A: 体験レビュー型（55スキ参考）
1. 「実はいまこういう実験してます」で始める
2. 時系列で体験を語る（臨場感重視）
3. 使い方をステップ化してまとめる
4. 「なぜこれがすごいのか」を技術的に解説
5. 事業・哲学に接続する

### TYPE B: 哲学・思想型（94スキ参考）
1. 根源的な問いを投げる（「愛って何？」）
2. 既存の答えを片っ端からぶった切る（歴史的レビュー）
3. 「で、全部使えない」と結論
4. 「わたしの答えはこれ」と独自の定義を提示
5. その定義であらゆる事例を説明してみせる
6. 哲学・事業に着地
7. 「あなたもそう思いませんか」で締め + P.S.

### TYPE C: 会社ストーリー型（18スキ参考）
1. 「久しぶりに書いてます」的な距離感で始める
2. 自分の人生ストーリーを時系列で語る
3. ストーリーの中で哲学が形成される過程を見せる
4. 哲学 → 事業 → ビジョンの順で展開
5. 「力を貸してください」で締め + P.S.

### TYPE D: ビジョン・プロダクト型（175スキ参考）
1. 「最近こんなことがあった」で始める
2. 業界の現状を分析して「全部死ぬ」と断言
3. 自社の独自ポジションを明確化
4. 新概念を定義・説明
5. 具体的なユースケースで読者に想像させる
6. 哲学的な意味づけ → 壮大なビジョン

## 締めのパターン

### 必ず含める要素
1. 読者への呼びかけ（「一緒に」のスタンス）
2. 「ここまで読んでいただき、ありがとうございました。」で締め

### P.S. テンプレート
```
P.S. （裏話や本音）
P.P.S. （関連情報や宣伝）
P.P.P.S. （ユーモアのあるひとこと）

（日付）
```

## noteエディタのフォーマット制約

noteのテキストエディタで使える記法は以下のみ:

- 見出し: `# ` と `## ` の2段階のみ（`###`以下はnoteで反映されない）
- 箇条書き: `- ` `* ` `+ `
- 番号付きリスト: `1. `
- 引用ブロック: `> ` `>> `
- 区切り線: `---`
- 太字: noteエディタ上でテキスト選択→Bで設定（`**text**`は反映されない）
- テーブル（表）: 使えない → 箇条書きで代替
- コードブロック: 使えない → 引用ブロックで代替
- 画像: エディタ上で挿入（Markdownの`![alt](url)`は使えない）

### 下書きファイルの書き方ルール

下書きMarkdownでは `**太字**` や `###` を使ってOK（読みやすさのため）。
noteに貼り付けるときに以下の変換が必要:
- `###` → `##` に変換
- `**太字**` → noteエディタ上で手動で太字にする
- テーブル → 箇条書きに変換
- コードブロック → 引用ブロック or 本文に変換

## NGパターン（Maloncafeっぽくない）

- 「〜させていただきます」的な丁寧すぎる敬語
- 一文が80文字を超える長文
- 見出しが「1. はじめに」「2. 本論」みたいな教科書スタイル
- 太字が全く使われていない
- 改行が少なくて段落が5行以上続く
- 体験談やエピソードが一切ない
- 「笑」が一度も出てこない
- P.S.がない
- 一人称が「わたし」以外
