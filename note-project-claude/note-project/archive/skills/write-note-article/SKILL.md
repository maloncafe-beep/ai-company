# write-note-article スキル

## 発動トリガー
「記事書いて」「〜について書いて」「下書き作って」

## 執筆開始の前提条件（必須）

以下が揃っていない場合、執筆を開始しない：

**社会問題・分析系テーマの場合**
- [ ] `research-topic`スキルのStep1〜2が完了している
- [ ] リサーチメモがユーザーに確認・合意されている
- [ ] タイトル・切り口が確定している

**体験・感情系テーマの場合**
- [ ] ヒアリングで体験談の素材が十分に揃っている
- [ ] 記事の構成（骨格）をユーザーと合意している

→ **どちらも「構成の合意」なしに書き始めない。**

---

## 実行手順

### Step 1: 設定ファイルの確認
必ず以下を参照してから執筆開始:
1. `config/author-profile.md`
2. `config/writing-style-guide.md`
3. `config/company-philosophy.md`
4. テーマに対応するテンプレート（`templates/`）

### Step 2: 記事タイプを確定
| タイプ | 判断基準 |
|--------|---------|
| TYPE A 体験レビュー型 | 実際の体験・ツール・サービスの話 |
| TYPE B 哲学・思想型 | 根源的な問いを立てる話 |
| TYPE C 個人ストーリー型 | 自分の軌跡・節目・気づきの話 |
| TYPE D トレンド分析型 | トレンドを分析して実務活用法を渡す |

### Step 3: 執筆チェックリスト
執筆中・執筆後に必ず確認:

**文体**
- [ ] 一人称は「わたし」
- [ ] 冒頭はテーマに合った「つかみの一文」で始める（定型句禁止）
- [ ] 「こんにちは！ご機嫌いかがですか。」は使わない
- [ ] AI使用の開示は入れない（必要な場合のみ記事末尾に一言）
- [ ] 太字を超多用している
- [ ] 一文60文字以内
- [ ] 「笑」が1セクション1〜2回使われている
- [ ] P.S. / P.P.S. / P.P.P.S. がある
- [ ] 「ありがとうございました。」で締めている

**冒頭のつかみパターン（テーマ別に選ぶ）**
- 共感型：読者の状況をそのまま描写する（「〜ということ、ありませんか？」）
- 未来志向型：「こうだったらいいと思いませんか？」で理想を先に提示
- 問いかけ型：根源的な問いを一文で投げる
- シーン描写型：具体的な場面から入る
- 断言型：結論を最初に言い切る

※つかみの良し悪しがスキ数を左右する。定型句に逃げない。

**構成**
- [ ] 冒頭3行でフックがある
- [ ] 読者への問いかけが複数ある
- [ ] 体験談・具体例がある
- [ ] 哲学（Well-being/LTR/Giver・Taker/価値提供）に着地している
- [ ] 4000文字以上

**noteフォーマット**
- [ ] 見出しは`#`と`##`のみ（`###`不使用）
- [ ] テーブル不使用（箇条書きで代替）
- [ ] `**太字**`はnote貼り付け時に手動変換が必要と認識

### Step 4: ファイル保存
```
articles/drafts/YYYYMMDD-タイトル.md
```

フロントマター（YAMLヘッダー）を必ず記述:
```yaml
---
title: 記事タイトル
status: draft
created: YYYY-MM-DD
tags: [タグ1, タグ2]
article_type: A/B/C/D
estimated_read_time: ○分
ai_disclosure: "AIと一緒に執筆・推敲。体験と論旨は著者のもの。"
---
```

## NGパターン（絶対に避ける）
- 「させていただきます」
- 一文80文字超
- 「1. はじめに」スタイルの見出し
- 太字ゼロ
- P.S.なし
- 「わたし」以外の一人称
- 「こんにちは！ご機嫌いかがですか。」で始める
- 「今日もAIに助けてもらっています」などのAI開示を冒頭に入れる
- 定型句で冒頭を逃げる（つかみは毎回考える）
