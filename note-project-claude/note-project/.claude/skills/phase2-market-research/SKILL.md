# phase2-market-research スキル

## 発動トリガー
「市場調査して」「このテーマの競合調べて」

## 目的
フェーズ1で絞ったテーマ候補について、note内の人気テーマ・競合訴求・価格帯を調べ、「勝ちやすい切り口」と「価格帯の相場」を一覧化する。

## 前提条件
- `products/YYYYMMDD-案件スラッグ/01-theme-candidates.md` が存在すること

## 実行手順

### Step 1: 調査項目
1. 同テーマ・類似テーマの既存有料note（タイトル、価格、訴求ポイント）
2. 売れている記事に共通する構成・切り口
3. 価格帯の相場

note.com内の情報はWeb検索・note内検索で調べる。実在するデータのみを使い、出典が不明な数字は「推定」と明記する。

**AI記事量産アカウントに注意（2026-10-01追加）：** note.com、特に「転職」ジャンルには、同一運営元とみられるAI記事量産アカウント群が存在することを確認済み（14時間前／19時間前／23時間前／1日前×数件／2日前という投稿間隔が複数アカウントで完全一致、「#はじめてのnote」タグ、「Xは／が、Yするか｜整理する」型の定型タイトル、が目印）。競合記事数・スキ数を調査する際、こうしたアカウントの記事を「売れている一般的な競合」として過大評価しない。

### Step 2: データポイント表を作成
最低10項目以上：

| 観点 | 一般的な傾向 | 実際の事例/データ | 出典 | この商品への示唆 |
|------|------------|------------------|------|----------------|
| | | | | |

### Step 3: 売れる/売れないの判断を下す（2026-09-30追加：この判断はClaude Code側の権限であり責任）

表の下に以下を明記する：
- 勝ちやすい切り口の結論（3つに絞る）
- 推奨価格帯
- **Go/No-Go判定**：この調査結果を踏まえて、このテーマで進めるか（Go）、テーマ自体を見直すか（No-Go）を明記する。判断材料の例：直接競合が強すぎて差別化できない、価格帯が極端に低く収益にならない、需要そのものが確認できない、等

No-Goと判断した場合は、フェーズ1に戻って別テーマを検討し直す（経営者に確認を取る必要はない。テーマ変更の経緯を`LOG.md`に残せば十分）。

### Step 4: 保存
`products/YYYYMMDD-案件スラッグ/02-market-research.md` に保存する。

### Step 5: LOG更新
`products/YYYYMMDD-案件スラッグ/LOG.md` に、調査で分かった数字・学びを1行以上追記する（CLAUDE.mdの「数字で語れ」原則）。

## 次のフェーズへ
立ち止まらず、自分で切り口・価格帯を決めて `phase3-product-design` スキルに進む（2026-09-30更新：一気通貫がデフォルト。経営者の実作業はnote/X投稿のみのため、判断はClaude Code側で進めてよい）。
