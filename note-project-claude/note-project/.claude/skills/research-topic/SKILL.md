# research-topic スキル

## 発動トリガー
「○○について調べて」「リサーチして」「データ集めて」

## テーマ判定（最初に必ず行う）

### Claudeが得意なテーマ（社会問題・AI・ビジネス分析系）
- Web検索でデータ・ファクトが取れる
- 構造化・比較分析しやすい
- → **Step1〜4をフルで実行**

### Claudeが苦手なテーマ（体験・感情・人間関係系）
- データが薄く、骨格が作りにくい
- ヒアリング依存になる
- → **「このテーマはデータが取りにくいです。体験談で補いますが、構成を先にヒアリングで固めますか？」とASKする**
- → 無理に記事を書き始めない

## 実行手順（社会問題・分析系テーマ）

### Step 1: 市場リサーチ
noteで類似記事の傾向・空白を調べる。

確認事項：
- 同テーマの記事はどれくらいあるか（飽和度）
- 読まれている記事の共通点（タイトル・構成・切り口）
- **空白はどこか**（Maloncafeが差別化できる場所）

→ 「○○というポジションで差別化できます」を提示してユーザーに確認

### Step 2: トピックリサーチ
Web検索でデータ・ファクトを収集。以下の項目を必ず揃える：

**① キーデータ（表形式・出典付き・10個以上）**

| データ | 数値 | 出典・時点 |
|--------|------|------------|
| | | |

**② 問題の構造整理（2〜4層の対照表）**

| 層 | 何が起きているか | 問題の性質 |
|----|-----------------|------------|
| | | |

**③ ぶった切り候補（常識→実態の対照表）**

| よくある常識 | 実態・ぶった切り |
|------------|----------------|
| | |

**④ 今後の方向性・仮説（3〜5個）**

**⑤ 哲学との接続ポイント**
- Well-being：
- LTR：
- Giver・Taker：
- 価値提供：

**⑥ 記事の切り口候補（タイトル案3つ以上）**

### Step 3: ユーザーに確認（必須・ここで止まる）
リサーチメモを提示して以下を確認：
- データ・構造の方向性に合意を得る
- タイトル・切り口を確定する
- **OKが出るまで執筆しない**

### Step 4: リサーチメモを保存
保存先: `research/YYYYMMDD-テーマ名.md`

---

## 記事執筆への引き渡し
Step3でOKが出たら`write-note-article`スキルへ。
リサーチメモが骨格になる。肉付けはMaloncafe文体で。
