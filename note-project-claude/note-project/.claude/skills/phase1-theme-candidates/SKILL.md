# phase1-theme-candidates スキル

## 発動トリガー
「note商品のテーマ考えて」「売れそうなテーマ探して」「新しい案件始めたい」

## 目的
市場起点で有料note商品のテーマを決め、次のフェーズに進む。著者が書きたいテーマではなく、売れる条件から逆算する。

## 進め方（2026-09-30更新：一気通貫がデフォルト）

`config/project-brief.md`の「実行境界」に定めた通り、経営者の実作業はnote投稿・X投稿のみで、それ以外の判断はClaude Codeの裁量に委ねられている。そのため、**テーマ候補を複数出して選定を仰ぐのではなく、自分で1つに決めてフェーズ2以降まで一気に進め、完成した状態（またはフェーズ6の提示直前）まで来てから経営者に見せる**のをデフォルトの進め方とする。

複数候補を出して選んでほしいと明示的に頼まれた場合のみ、旧来通り3候補を提示して選定を待つ（このSKILL末尾に手順を残す）。

## 前提
- `config/project-brief.md` を必ず参照する。テーマは「ビジネス・AI・仕事まわりは全般的にOK」が基本方針
- 参入したい分野の指定がなければ、市場調査ベースで自分で決める

## 実行手順（デフォルト：一本化して進める）

### Step 1: テーマ候補を検討する（内部検討でよい、複数出して確認を仰がない）
以下の条件を満たすかで比較し、最も妥当な1つを選ぶ：
1. 読者の「悩み」「欲しい結果」「購入動機」が明確に言語化できるか
2. 競合が少ない、または差別化できる切り口があるか
3. 1商品で終わらず、続編・派生商品に展開できる余地があるか

### Step 2: 案件フォルダを作成
```
products/YYYYMMDD-案件スラッグ/
```
`products/_TEMPLATE/` の中身をコピーして雛形とする。

### Step 3: 選定結果を記録
`products/YYYYMMDD-案件スラッグ/01-theme-candidates.md` に、検討した中で選んだテーマとその理由を記録する（比較検討した他の案があれば簡潔に残してもよい）。

### Step 4: LOG更新
`products/YYYYMMDD-案件スラッグ/LOG.md` と `products/INDEX.md` に着手記録を1行追記する。

### Step 5: 続けてフェーズ2〜5まで進める
立ち止まらず `phase2-market-research` 以降を順に実行し、フェーズ6の提示直前まで一気に仕上げる。

## 複数候補から選んでほしいと明示的に頼まれた場合のみ

- 候補を3つ生成し、各候補について「想定読者像（悩み／欲しい結果／購入動機）」「想定価格帯」「選ぶ理由」を`01-theme-candidates.md`に書く
- 経営者が候補から1つ選ぶまで待ってから `phase2-market-research` に進む
