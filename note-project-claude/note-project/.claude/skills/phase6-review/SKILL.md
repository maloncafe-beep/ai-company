# phase6-review スキル

## 発動トリガー
「レビューして」「確認お願いします」「公開前チェックして」

## 目的
フェーズ4・5の全生成物について、**人による最終承認**を得る。このフェーズはClaude Codeが自動で完了させてはならない。

## 前提：レビューの分担（2026-09-30決定・重要）

**「AI臭さ」「事実関係の正確性」は経営者側ではチェックしない。** 経営者のレビューは、テーマの適合・訴求力・公開するかどうかの意思決定が中心。したがって、以下はフェーズ4〜5の生成時点でClaude Code側が責任を持って担保する（このフェーズで初めて気づくのではなく、提示前に済ませておく）：

- **事実関係の正確性**：本文中の数字・市場データ・他社事例は、フェーズ2の市場調査で裏取りしたもの以外を断定的に書かない。裏取りできない場合は「一般的な傾向として」「推定」等を明記する
- **AI臭さの除去**：不自然に整いすぎた言い回し、抽象的な一般論の羅列、「〜することが重要です」のような中身のない結論文、テンプレ的な導入・締めを避ける。具体的な数字・具体例・固有の言い回しを残す

## 実行者
**経営者本人。** Claude Codeはチェックリストの提示・修正の反映のみを行い、承認そのものは代行しない。

## 実行手順

### Step 1: チェックリストを提示
`products/YYYYMMDD-案件スラッグ/06-review-checklist.md` に以下を出力し、経営者に確認を依頼する。

```markdown
# 公開前チェックリスト（フェーズ6）

□ 論理の一貫性（悩み→解決策→CTAの流れに矛盾がないか）
□ 「です・ます」調で統一されているか
□ 想定読者に対して訴求力があるか
□ テーマがアカウントの雰囲気から大きくずれていないか
□ サムネ画像が記事内容・タイトルと合っているか

（データ・事実の正確性とAI臭さの除去は、フェーズ4〜5でClaude Code側が担保済みのため、ここでのチェック対象外）

## 承認状況
- [ ] 未承認 / [ ] 承認済み（承認日: ）
```

### Step 2: 修正対応
修正がある場合、経営者から「修正箇所→修正理由→期待効果」を受け取り、該当する `04-content/` のファイルまたは `05-thumbnail/` の画像を修正する。修正後は再度チェックリストを提示する。

### Step 3: 承認の記録
経営者が承認したら、チェックリストの承認状況を更新し、`products/INDEX.md` のステータスを「承認済み」に更新する。

## 次のフェーズへ
**承認済みになるまで `phase7-publish-promote` に進まない。**
