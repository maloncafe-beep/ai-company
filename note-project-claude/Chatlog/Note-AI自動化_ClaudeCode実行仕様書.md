# Note-AI自動化 — Claude Code実行仕様書

## 前提条件

- 本プロジェクトは、既存のMALO/Maloncafeアカウント・ブランドとは**完全に分離した新規note.comアカウント**で運用する
- 既存プロジェクトが「著者起点（書きたいテーマが先）」であるのに対し、本プロジェクトは**「市場起点（売れる条件が先）」**で商品・テーマを決定する
- テーマは固定せず、市場調査の結果に応じて流動的に変える
- 収益モデルは有料note（本編＋特典＋購入後導線）
- note.comへの実投稿は**手動**（本仕様書はnote.com投稿の自動化を含まない）
- SNS告知は既存の `x-auto-post`（Python、Codexで手動トリガー、スプレッドシート連携）を流用する
- アカウント作成自体はログイン・認証を伴うため、**ユーザー本人が実施済み**であることを前提とする

## フェーズ1：売り先・読者像の決定

| 項目 | 内容 |
|------|------|
| **入力** | 参入したい大分野（任意、なければClaudeが市場調査から提案） |
| **成果物** | 想定読者の悩み・欲しい結果・購入動機の整理／狙うテーマ候補3つ |
| **成功基準** | 各候補に「なぜこのテーマなら売れるか」の根拠がある |

**Claude Code指示テンプレート：**
```
以下の条件で、有料note商品のテーマ候補を提案してください。

【背景情報】
- 参入したい分野（任意）：[記入、なければ「市場調査ベースで提案」]
- 想定価格帯（任意）：[記入]

【候補の条件】
1. 読者の「悩み」「欲しい結果」「購入動機」が明確に言語化できるか
2. 競合が少ない、または差別化できる切り口があるか
3. 1商品で終わらず、続編・派生商品に展開できる余地があるか

【出力形式】
各候補について：
- テーマ名
- 想定読者像（悩み／欲しい結果／購入動機）
- 想定価格帯
- 選ぶ理由
```

## フェーズ2：市場調査

| 項目 | 内容 |
|------|------|
| **入力** | フェーズ1で絞った候補テーマ |
| **成果物** | note内の人気テーマ・競合訴求・価格帯の一覧表（10項目以上） |
| **成功基準** | 「勝ちやすい切り口」と「価格帯の相場」が表で一目瞭然 |

**Claude Code指示テンプレート：**
```
以下のテーマについて、note.com内の市場調査を行ってください。

【テーマ候補】
[フェーズ1の出力をペースト]

【調査内容】
1. 同テーマ・類似テーマの既存有料note（タイトル、価格、訴求ポイント）
2. 売れている記事に共通する構成・切り口
3. 価格帯の相場

【出力形式：データポイント表】
| 観点 | 一般的な傾向 | 実際の事例/データ | 出典 | この商品への示唆 |
|------|------------|------------------|------|----------------|
| [観点1] | | | | |

表の下に：
- 勝ちやすい切り口の結論（3つに絞る）
- 推奨価格帯
```

## フェーズ3：商品設計図の作成

| 項目 | 内容 |
|------|------|
| **入力** | フェーズ2で確定した切り口・価格帯 |
| **成果物** | 本編構成・特典・購入後導線を含む商品設計図 |
| **成功基準** | 1商品で終わらない収益構造になっている |

**Claude Code指示テンプレート：**
```
以下の切り口で、有料note商品の設計図を作成してください。

【確定した切り口】
[フェーズ2の結論]

【設計項目】
1. 本編note：見出し構成、想定文字数
2. 特典：購入者限定コンテンツの内容
3. 購入後導線：次に案内する商品・サービス
4. 価格：[フェーズ2の推奨価格帯]

【出力形式】
- 本編構成（見出しごとに1文で要約）
- 特典内容
- 購入後導線（低価格note→まとめ商品→上位サービスの流れ）
```

## フェーズ4：コンテンツ生成（本文・販売ページ・告知文）

| 項目 | 内容 |
|------|------|
| **入力** | フェーズ3の商品設計図 |
| **成果物** | 本文、販売ページ文、購入特典文、SNS告知文一式 |
| **成功基準** | 導入・問題提起・解決策・具体例・特典・CTAが揃っている |

**Claude Code指示テンプレート：**
```
以下の設計図に基づき、有料note記事の本文一式を執筆してください。

【商品設計図】
[フェーズ3の出力をペースト]

【執筆条件】
- 「です・ます」調
- 修辞的表現より実証性を優先（データ・事例ベース）
- 導入→問題提起→解決策→具体例→特典→CTAの流れ

【出力形式】
1. 本文（本編note）
2. 販売ページ説明文
3. 購入特典文
4. SNS告知文（X／Threads用、複数パターン）
5. LINE案内文（該当する場合）
```

## フェーズ5：サムネ・表紙画像の生成

| 項目 | 内容 |
|------|------|
| **入力** | フェーズ4で確定したタイトル・記事内容 |
| **成果物** | サムネ画像（表紙用） |
| **使用ツール** | Higgsfieldコネクタ（Nano Banana Pro／Nano Banana 2） |

**Claude Code指示：**
```
Higgsfieldコネクタを使い、以下の記事のサムネ画像を生成してください。

【記事タイトル・内容】
[フェーズ4の出力をペースト]

【生成方針】
- 品質重視の場合：Nano Banana Proを使用
- 量産・速度重視の場合：Nano Banana 2を使用
- テキストを画像内に含める場合は、可読性を優先したレイアウトにする
```

## フェーズ6：レビュー・検証（人による必須確認）

| 項目 | 内容 |
|------|------|
| **入力** | フェーズ4・5の全生成物 |
| **成果物** | 承認 or 修正指示 |
| **実行者** | **ユーザー本人（このステップは自動化しない）** |

**チェックリスト：**
```
□ データ・事実の正確性
□ 論理の一貫性（悩み→解決策→CTAの流れに矛盾がないか）
□ 「です・ます」調で統一されているか
□ 想定読者に対して訴求力があるか
□ サムネ画像が記事内容・タイトルと合っているか

修正がある場合：修正箇所→修正理由→期待効果をClaude Codeに渡す
```

---

## フェーズ7：投稿・告知（実行）

| 項目 | 内容 | 実行方法 |
|------|------|---------|
| note.comへの投稿 | 本文・タイトル・タグ・価格設定・公開 | **手動**（コピペ） |
| SNS告知 | X（Twitter）への告知投稿 | `x-auto-post`（Python、Codexで手動トリガー） |

**実行事項：**
```
1. note.comに本文・タイトル・タグ・価格を手動で入力し、下書き保存
2. 最終確認後、公開
3. x-auto-post を実行し、SNS告知を行う（該当するスプレッドシートに記事URLを記入してからトリガー）
```

## 制約事項・注意点（Claude Codeが認識しておくべき前提）

- note.comは記事投稿・編集用の**公式外部連携APIを公開していない**。本仕様書はnote.comへの自動投稿を含まないため、この制約による直接的な影響はないが、将来的に投稿自動化を検討する場合は、非公式ツール（Playwright等によるブラウザ操作）に依存することになり、UI変更への保守対応と利用規約上のグレーゾーンが伴う点に留意すること
- アカウント作成・ログインはClaude Codeが代行できない操作であり、ユーザー本人が行う
- フェーズ6（レビュー・検証）は自動化の対象外。必ず人の承認を経てからフェーズ7に進むこと
