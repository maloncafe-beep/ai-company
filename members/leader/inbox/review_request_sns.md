# 設計変更報告：ファイル管理ルール刷新（thread-19以降から適用）

## 背景
既存のナンバリング設計に3系統の番号混在が発覚（スレッドNN / リメイクNN / スプシID）。
ローカルファイルだけで対応関係・投稿予定が追えない状態だったため、thread-19以降を対象に設計を刷新。

## 変更内容

### 1. ファイルNN統一（Writer CLAUDE.md）
- スレッド/リメイク/画像プロンプトは同じNNを使う
  - 例：`x-thread-19` / `x-remix-19` / `x-prompt-19`
- リメイクに独自連番を振らない

### 2. `元スレッドID` 廃止（Writer CLAUDE.md）
- フロントマターからスプシIDへの参照を除去
- NNが一致していれば対応関係は自明

### 3. 投稿予定日をSNSがファイルに書き戻す（SNS / Writer CLAUDE.md）
- Writerは `投稿予定日:` を空欄で作成
- SNSがスプシ登録後にフロントマターへ記入
- これによりローカルファイルだけで投稿スケジュールが確認可能に

## 既存ファイル（thread-01〜18）
