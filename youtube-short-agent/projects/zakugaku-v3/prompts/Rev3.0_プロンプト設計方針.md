# Rev3.0 プロンプト設計方針

## 目的

雑学ショート Rev3.0 のプロンプトを変更するときの判断基準を残す。

この資料は、`Chatlog/ショート動画トレンド2026.md`、過去のプロンプト、投稿分析ログを参考にする。ただし、外部資料の市場データやアルゴリズム説明は未検証のものも含まれるため、運用ルールではなく「検証する仮説」として扱う。

## Rev3.0 で守る中心方針

Rev3.0 は、従来の「1本に7〜10雑学を詰める型」から離れ、1つの疑問・誤解・違和感を1〜2分で深掘りする型にする。

狙いは、単なる情報量ではなく、視聴者が見終わったあとに「見方が1つ変わった」と感じること。

## 採用するトレンド要素

### 1. 冒頭3秒を最重要にする

- 1秒目で何の話か分かる
- 3秒以内に「自分ごと」か「意外性」が伝わる
- 静止した説明開始ではなく、画面上の動き、強い一文、表情、対比のどれかを入れる

冒頭で使いやすい型:

- 意外な結論: 「実は、〇〇な人ほど△△している」
- 誤解の反転: 「〇〇が原因だと思われがちですが、本当は違います」
- 自己診断: 「これをしている人は、疲れやすくなっています」
- 問いかけ: 「なぜ、頑張る人ほど続かないのか」

### 2. 1テーマを深掘りする

雑学を増やして尺を作らない。

1本の中で扱うのは、以下のどれか1つに絞る。

- 1つの悩み
- 1つの誤解
- 1つの行動
- 1つの心理
- 1つの習慣

リスト型やランキング型は、従来の量産雑学に戻りやすいため、Rev3.0 では原則として使わない。使う場合も、ランキング全体ではなく「1位の理由を深掘りする」方向に寄せる。

### 3. 45〜75秒の高密度型を基準にしつつ、1〜2分まで許容する

外部資料では45〜75秒の高情報密度が有効とされているが、このチャンネルでは60〜120秒の深掘り型も検証対象にする。

ただし、75秒を超える場合は、次の条件を満たす。

- 同じ説明を繰り返していない
- 途中で視点転換がある
- 具体例、理由、行動の3要素が入っている
- 視聴者がコメントしやすい問いが最後に残る

### 4. 3〜5秒ごとに画面変化を入れる

台本だけでなく、映像側にも変化を設計する。

変化として使うもの:

- テロップの位置変更
- 図解
- 拡大、ズーム、寄り引き
- 表情差分
- 背景色の切り替え
- NG行動とOK行動の比較
- キーワードだけを大きく出す画面

毎回AI生成画像に頼らなくてもよいが、同じ素材をそのまま貼るだけの印象は避ける。

### 5. コメント・保存につながる余韻を作る

最後は説明で終わらせない。

使いやすい終わり方:

- 「あなたは、どちらをやりがちですか」
- 「これ、心当たりがある人はコメントで教えてください」
- 「あとで見返せるように保存しておいてください」
- 「今日1つだけ試すなら、どれにしますか」

コメント誘導は強制感を出さず、視聴者が自分の経験を書きやすい問いにする。

## 使わない方向の表現

以下は、時代遅れ感や量産感が出やすいため、原則として避ける。

- 99%が知らない
- 知らないと損する
- 絶対にやってはいけない
- 〇〇するだけで人生が変わる
- 根拠のない断定
- スピリチュアル、引き寄せ、運頼み

ただし、「損する」「やってはいけない」に近い意味でも、具体的な生活場面に落とせる場合は使える。

例:

- NG: 知らないと損する健康法
- OK: 健康に良さそうで、実は効果が薄い習慣

## プロンプトを変更するときのルール

### 1. 変更理由を先に書く

プロンプトを変える前に、必ず以下を残す。

- 何が問題だったか
- どの指標を改善したいか
- どの仮説を試すか
- 何本で判定するか

例:

```text
問題: 視聴を継続が30%前後で止まっている
仮説: 冒頭で自分ごと化できていない
変更: 冒頭3秒に自己診断型フックを追加
判定: 3本投稿して、視聴を継続40%以上を目安に確認
```

### 2. 一度に変える変数を増やしすぎない

同時に変えると、何が効いたのか分からなくなる。

できるだけ分ける変数:

- 台本構成
- タイトル
- サムネ
- 画面構成
- ナレーション速度
- 投稿時間
- 公開予約数
- 素材の種類

特に、インプレッションが極端に低い場合は、内容の良し悪しではなく、ショートフィードに乗っていない可能性を先に疑う。

### 3. ルールを足すだけにしない

プロンプトは長くなるほど、出力が散らばりやすい。

新しいルールを追加する場合は、古いルールのうち不要なものを削る候補として記録する。ただし、実際のファイル削除や大きな削除編集は行わず、`LOG.md` に「削除候補」として残す。

### 4. 文字数と尺の指定を矛盾させない

以下のどれを狙うか、プロンプト内で明確にする。

- 45〜75秒: 高密度、テンポ重視
- 75〜120秒: 深掘り、共感、行動提案重視
- 120秒以上: Shortsとして使う場合は、構成の山を明確にする

「短くテンポよく」と「深く読ませる」を同時に強く指定しない。

## 評価の切り分け

評価は次の順番で見る。

1. インプレッション
2. 視聴回数
3. エンゲージビュー
4. 視聴を継続
5. 平均視聴率
6. 登録者増加
7. コメント
8. ショートフィード終了後の伸び

### インプレッションが極端に低い場合

台本評価を急がない。

疑うもの:

- 公開予約数を増やした影響
- 同系統動画の連続投稿
- サムネとタイトルの初見弱さ
- AI量産コンテンツのように見える可能性
- YouTube側の一時的なシステム要因

### インプレッションはあるが視聴を継続が低い場合

台本と冒頭を疑う。

確認するもの:

- 冒頭3秒で自分ごと化できているか
- タイトルと中身がずれていないか
- 説明が抽象的すぎないか
- 中盤に変化があるか
- 最後まで見たくなる問いがあるか

## テスト単位

1つのプロンプト変更は、最低3本で判断する。

1本だけでは、テーマ、投稿時間、YouTube側の露出差、初動の偶然を切り分けにくい。

判定メモに残すもの:

- プロンプト版
- 公開順
- タイトル
- 尺
- 投稿時刻
- サムネ方針
- 視聴回数
- EngView
- 視聴を継続
- 平均視聴率
- 登録者増加
- コメント
- 次に変える点

## ファイル運用

プロンプトは `prompts/` に保存する。

推奨ファイル名:

```text
Rev3.0_1雑学ショート台本プロンプト.md
Rev3.1_冒頭3秒強化プロンプト.md
Rev3.2_コメント誘導強化プロンプト.md
```

大きく変えた場合は、既存ファイルを直接壊さず、別バージョンとして作る。

変更したら `LOG.md` に、なぜ変えたか、何を変えたか、どう検証するかを残す。

## 次に試す優先順位

1. 1雑学1本、1〜2分の深掘り型を3本作る
2. 冒頭3秒を自己診断型、誤解反転型、意外な結論型で比較する
3. 公開予約は一時的に1〜2本までに抑えて様子を見る
4. サムネと冒頭1秒の見え方を毎回変える
5. ショートフィード終了後に少しずつ伸びるかを追う

## Rev3.2 の追加方針

2分前後の動画では、中盤と終盤で離脱が起きやすい。

そのため、Rev3.2では以下を追加する。

- 4番付近に「中盤パンチ」を入れ、視点を一度ひっくり返す
- 7番を行動指示ではなく「余韻の儀式」にする
- 余韻の儀式では、テーマに合う心理的な儀式を1つ入れる
- 最後は定番として「眠る前に今日できたことを1つだけ思い出す」で締める

狙いは、対症療法的なノウハウではなく、動画を見終わったあとも残る小さな習慣を渡すこと。
