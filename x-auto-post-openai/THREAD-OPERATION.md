# Thread-First Operation

このファイルは、現在の `x-auto-post` の実運用ルールをまとめたメモです。
古い README / セットアップ文書に `remix` 前提の説明が残っていても、日常運用ではこのメモを優先してください。

## Current Policy

- 基本運用は `thread` のみ
- `remix` は使わない
- 必要なときだけ `single` を作る
- 下書きはローカルファイルではなく Google スプレッドシートに追加される

## Recommended Commands

### Google認証トークン切れ／失効

```bash
node auth-google.mjs
```

### Thread を1本作る

```bash
node tools/generate-posts.mjs --count 1 --type thread --theme "日常で違和感を感じたこと。ズレや違和感をそのまま疑問として書き出し、その原因を探る。スレッドの最後に固定タグを付与する。#違和感 #気づき"
```

### Single を1本作る

```bash
node tools/generate-posts.mjs --count 1 --type single --theme "任意のテーマ"
```

### 投稿前確認

```bash
node tools/post-to-x.mjs --dry-run
```

### 実投稿

```bash
node tools/post-to-x.mjs
```

## Execution Prompts

### Thread 用

```text
日常で違和感を感じたことをテーマに、Xスレッドを1本作ってください。
ズレや違和感をそのまま疑問として書き出し、その原因を探る流れにしてください。
構成は「現象 → ズレ → 構造仮説 → 次の実験」。
合計2ツイートに収めてください。
1ツイート目は【現象】本文 + 【ズレ】本文 + #違和感 #気づき。
2ツイート目は【構造仮説】本文 + 【次の実験】本文。
【現象】と【ズレ】を同じツイート内でつなげると、読者が「何がずれているのか」を理解しやすい。
【構造仮説】と【次の実験】も同じツイート内でつなげると、仮説だけが浮かず、次の行動まで意味が通りやすい。
営業色の強い話は避けて、内省と気づきが残る書き方にしてください。
```

### Single 用

```text
日常で感じた違和感をひとつ選び、1ツイートで完結する形にしてください。
結論を急ぎすぎず、ズレの発見が伝わる文にしてください。
```

## How Thread Is Stored

スレッド本文は、スプレッドシートの「投稿文」セルに `---` 区切りで保存されます。

```text
【現象】本文【ズレ】本文 #違和感 #気づき
---
【構造仮説】本文【次の実験】本文
```

`node tools/post-to-x.mjs --dry-run` 実行時に `スレッド（nツイート）` と表示されれば、投稿時もスレッドとして扱われます。
タイムラインで折り畳まれにくくするため、通常運用では `スレッド（2ツイート）` にします。
合計4ツイートにすると、2通目以降が「返信をさらに表示」に入ることがあります。

## Spreadsheet Workflow

1. `generate-posts` で下書きを追加
2. スプレッドシートで内容確認
3. 投稿したい行だけ `承認済み` に変更
4. `--dry-run` で確認
5. 問題なければ実投稿

## Notes

- `--count 2` は「2件生成」の意味です
- `--type thread` を付けたときだけ、thread 形式を強制します
- `--type single` を付けたときだけ、single 形式を強制します
