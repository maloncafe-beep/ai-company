# note運用チェックリスト

詳細な分析ログは `research/note-pdca-ledger.md`。このファイルは、投稿前後に見る短い実務用チェックリスト。

## 基本方針

- フォロワー獲得や交流を目的にしない。
- 最終目的は、1本で深く整理できる違和感を見つけ、有料記事として成立するか探索すること。
- スキ数は主KPIにしない。スキは一覧スキ、応援スキ、AI/自動化反応、関係性反応を含む。
- 主に見るのは、掲載カテゴリ、初動インプレッション、初動PV、表示→PV率、7日後PV。
- マガジンは課金導線ではなく、内容のカテゴリ分けとして使う。

## 投稿前チェック

- [ ] この記事は、違和感収集家側の記事か。ZODIAC側や一般作業の文脈が混ざっていないか。
- [ ] 1本で深く整理できる違和感に近いか。
- [ ] 自分が面倒くささを超えて整理したいテーマか。
- [ ] タイトル表示だけで、誰のどんな違和感かわかるか。
- [ ] 最初の1行で、読者が「自分の話かも」と思えるか。
- [ ] 最初の1行を、あいさつや抽象論で消費していないか。
- [ ] 想定掲載カテゴリはどこか。
- [ ] タグは、掲載カテゴリと関連記事の両方を意識しているか。
- [ ] サムネ文字は一覧で読める大きさか。
- [ ] スマホ一覧でも主要文言が読めるか。

## サムネ確認

- [ ] 通常記事は、短い強い言葉型になっているか。
- [ ] 主文言は2行以内か。
- [ ] 文字は大きく太いか。
- [ ] 色は散らかっていないか。基本は3色程度か。
- [ ] 同じキャラ/世界観でブランド感があるか。
- [ ] 記事内容やアカウントの雰囲気とズレていないか。
- [ ] 有料記事の場合、無料記事より「読む理由」「買う理由」が見えるか。

## 公開直後チェック

- [ ] 掲載カテゴリを確認する。
- [ ] 公開直後のスキでぬか喜びしない。数分以内のスキはAI/自動化/クロールの可能性を見る。
- [ ] スキしたユーザーを目視し、ざっくり傾向だけメモする。
- [ ] AI/自動化っぽいアカウントは重く見ない。
- [ ] 専門家っぽい人のスキがあれば、質的シグナルとしてメモする。

## 24時間後チェック

- [ ] インプレッションを記録する。
- [ ] PVを記録する。
- [ ] 表示→PV率を計算する。
- [ ] スキ数は参考程度に見る。
- [ ] インプレッションが多くPVが低い場合、タイトル表示と最初の1行を疑う。
- [ ] PVが少なくスキが多い場合、一覧スキ/応援スキ/自動化反応の可能性を見る。

## 7日後チェック

- [ ] 7日後PVを記録する。
- [ ] 初動だけで止まったか、後から読まれているかを見る。
- [ ] 関連記事や有料記事へのPVが増えたかを見る。
- [ ] 質問箱を置いた場合、内容に読後反応があるか見る。
- [ ] 有料記事候補にするほど、深く整理できる違和感だったか判断する。
