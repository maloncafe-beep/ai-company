# 記事リサーチ起点の2パターン

Maloncafeの記事自動化では、最初に「どこから作る記事か」を判定する。

記事の入口は大きく2種類。

ただし、起点がない場合は、先に `ideas/_trend-keyword-intake.md` に沿って流行キーワード・注目用語・SNS上の違和感語を候補出しする。

候補を出した段階では記事化しない。まろさんが「ピッと感じる」ものを選んでから、深掘りリサーチに進める。

## Route A: Xリサーチ起点

X上で見つけた違和感、言葉、反応、論点から記事を作る。

向いているテーマ:

- `普通わかるでしょ`
- `正論なのに苦しい`
- 何気ない投稿にある、言葉になっていない引っかかり
- SNS上で繰り返し出てくる不満・違和感・分断

狙い:

- インプレッションを取りやすいテーマを拾う
- 読者がすでに感じている違和感に名前をつける
- タイミングがはまる記事を作る

構成の流れ:

1. Xで反応がある言葉・状況を拾う
2. その言葉の奥にある前提を仮説化する
3. note内・Webで近いテーマを確認する
4. 「なぜそれが苦しいのか」を構造化する
5. Maloncafeの思想で置き直す

記事タイプ:

- `philosophy.md`
- `vision-product.md`

保存時メタデータ:

```yaml
source_route: x_research
source_signal: X上の反応・投稿・言葉
```

## Route B: 用語・概念リサーチ起点

外部記事、ニュース、専門用語、心理学・認知バイアスなどの概念から記事を作る。

向いているテーマ:

- 追認バイアス
- ツイニングバイアス
- 認知バイアス
- 結晶性知能
- 新しい社会現象・心理現象・ビジネス用語

狙い:

- タイムリーな用語を、読者の実感に翻訳する
- ただの解説ではなく、Maloncafeの違和感や思想に接続する
- 反応の濃い記事を作る

構成の流れ:

1. 注目した用語・概念を決める
2. 定義、背景、代表例を調べる
3. Gemini等も使い、状況・反対意見・日常例まで深掘りする
4. 深掘り結果を `research/YYYYMMDD-テーマ名.md` に落とす
5. その概念が日常のどんな違和感とつながるか探す
6. 既存の説明だけでは足りない点を出す
7. Maloncafeの思想で再定義する

記事タイプ:

- `philosophy.md`
- `company-story.md`
- `vision-product.md`

保存時メタデータ:

```yaml
source_route: concept_research
source_signal: 外部記事・ニュース・専門用語・心理学用語
```

## 使い分け

| 観点 | Route A: Xリサーチ | Route B: 用語・概念リサーチ |
|------|---------------------|------------------------------|
| 強み | 今の読者の反応を拾いやすい | 深い構造化・思想接続がしやすい |
| 伸び方 | インプレッションが出やすい | スキ・保存・フォローにつながりやすい可能性 |
| 弱点 | 流行に寄りすぎると浅くなる | 解説記事になるとMaloncafeらしさが薄くなる |
| 必須の変換 | SNSの違和感を構造にする | 用語を読者の実感に翻訳する |

## 深掘り必須ルール

どちらのルートでも、検索結果から直接記事を書かない。

特に `concept_research` では、用語解説だけで終わると浅くなる。記事を書く前に `research/_deep-research-method.md` に沿って、状況・背景・具体例・限界・Maloncafeとしての置き直しをMD化する。

反応が良かった記事は、用語や論点を見つけたあと、状況をかなり調べてMDに落とし、そこから構成していた。この工程を自動化でも省略しない。

## 自動化時の判定

最初に以下を確認する。

- Xで拾った言葉・投稿・反応が起点なら `x_research`
- 外部記事、ニュース、専門用語、心理学用語が起点なら `concept_research`
- 自分の経験が起点なら `personal_experience`
- 過去記事の横展開なら `past_article_extension`

起点が曖昧な場合は、記事化する前に `source_route` を決める。
