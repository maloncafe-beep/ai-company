# 自アカウント note PDCA（Cフェーズ）

書く前の市場調査は [research-note-market](../research-note-market/SKILL.md)。
本スキルは**公開後**の改善サイクル用。

## 現行方針（2026-10-07）

現在の「違和感収集家」分析では、スキ率中心ではなく、以下を優先する。

- 掲載カテゴリ
- 初動インプレッション
- 初動PV
- 表示→PV率
- 24時間後/7日後PV
- 回遊/有料記事PV
- スキしたユーザーのざっくり傾向

スキは記事を開かなくても押せるうえ、後から消える場合もある。スキ数やスキ率を主KPIにしない。フォロワー獲得や交流も目的にしない。

参照:
- `research/note-pdca-ledger.md` — 詳細分析ログ
- `research/note-operation-checklist.md` — 投稿前後の短い運用チェック

## ユーザーから受け取るデータ

いずれか（なければ取得方法を案内して停止）:

1. **ダッシュボードのスクショ**（アクセス状況・PV/スキ/コメント）
2. **CSV**（[Note Access Data Exporter](https://note.com/thracia776/n/n9328aa133862) 等でエクスポート）
3. **手動リスト**（記事タイトル, インプレッション, PV, スキ, 売上, 公開日）

公式CSVエクスポートはない。週1回ダッシュボード確認 → 月1回CSV or AI分析が推奨。

## ワークフロー

### Step 1: データ正規化
各記事について計算:
- **表示→PV率** = PV ÷ インプレッション × 100
- **スキ率** = スキ ÷ PV × 100（参考値。読後反応率とは扱わない）
- **1日あたりPV** = PV ÷ 公開日数（公開日不明なら概算日数を注記）
- **質問箱反応率** = 質問箱反応数 ÷ PV × 100（質問箱を設置した記事だけ参考値）

### Step 2: 3層分類
| 層 | 目安 |
|----|------|
| 露出あり | インプレッションが多い |
| 入口強い | 表示→PV率が高い |
| 深掘り候補 | PVは小さくても、テーマ適合・専門家スキ・回遊・有料記事PVの質的シグナルがある |
| 別系統 | PVは取れるが、違和感収集家本流とはズレる |

### Step 3: パターン抽出
- 掲載カテゴリとインプレッションの関係
- 表示→PV率が高い記事のタイトル表示・最初の1行・サムネ
- 7日後もPVが伸びる記事のテーマ
- スキ>PVの記事は、一覧スキ/応援スキ/AIクロールの可能性として扱う
- 専門家っぽい人のスキは、質的シグナルとしてメモする
- スキ数そのものではなく、誰が反応したかをざっくり見る

### Step 4: 有料化候補リスト
優先: 1本で深く整理できる違和感 ＋ 回遊/有料記事PVの関心 ＋ 自分が面倒くささを超えて書けるテーマ
スキ率やコメントは主条件にしない。売上なしは失敗扱いしない。

有料記事を既に出している場合:
- PV → 購入 → **CVR** の言及（[maa-note-analysis](https://github.com/Gajamarunosuke/maa-note-analysis) 利用時）

### Step 5: 次に書くテーマ5本
フィルタ軸:
- `config/company-philosophy.md`（Well-being / LTR / 価値提供 / AI・起業）
- ストック型キーワードの横展開
- `ideas/idea-pool.md` の未着手アイデア
- Xキーワード上位やリサーチから拾った違和感語
- 表示→PV率が高いタイトル型
- 深く整理できる有料記事候補

各テーマに: 理由（データ根拠）・想定掲載カテゴリ・入口タイトル案・有料記事候補度

### Step 6: 保存
`research/YYYYMMDD-account-pdca.md` に保存（テンプレート: `research/_pdca-template.md`）。

継続台帳として `research/note-pdca-ledger.md` にも、重要な施策・数字・仮説だけ追記する。

該当テーマの市場リサーチメモがある場合、`## 自アカウント指標` を更新する。

### Step 7: idea-pool 更新（ユーザーが依頼した場合のみ）
`ideas/idea-pool.md` の「入口予測」や優先度を、掲載カテゴリ・表示→PV率・7日後PV・類似テーマの実績に基づき★で更新。変更理由を1行メモ。

## 分析時の注意

- 競合スキ数との比較は意味が薄い。**自アカウント内の時系列・記事間比較**が正確
- 相互スキ・コミュニティ施策による水増しは自アカウントでも起こりうる → 異常値は注記
- 推測は「仮説」と明記する
- 公開直後数分のスキは、AI/自動化/クロールの可能性を見る。ぬか喜びしない。
- コメントは現在使わない前提。質問箱を置いた場合だけ質的反応として扱う。
- マガジンはカテゴリ分け。メンバーシップは基本的に考えない。

## 完了時の出力

1. 露出上位記事と表示→PV率
2. 入口が強い記事
3. 深掘り/有料記事候補
4. 次に試す施策（タイトル、最初の1行、サムネ、タグ、カテゴリ）
5. 保存パス
