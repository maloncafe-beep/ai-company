# 記事 推敲・ブラッシュアップ

## 現行方針（2026-10-07）

旧来の「バズ」「フォロー獲得」より、現在は以下を優先する。

- 1本で深く整理できる違和感があるか。
- タイトル表示と最初の1行で、一覧から開く理由があるか。
- フォロワー獲得や読者交流を目的にしていないか。
- スキ数やスキ率を過大評価しない。スキは一覧スキ、応援スキ、AI/自動化反応、関係性反応を含む。
- ZODIAC/zodiacm369 側のビジネス実務文体や量産感が混ざっていないか。
- 詳細は `research/note-operation-checklist.md` と `research/note-pdca-ledger.md` を参照する。

## ワークフロー

### Step 1: 記事を読む

### Step 2: リファレンス読み込み
以下を必ず読む:
- `config/author-profile.md`
- `config/writing-style-guide.md`
- `config/company-philosophy.md`

### Step 3: 多角的チェック（下記チェックリスト）

### Step 4: 改善提案をレポートで提示

### Step 5: ユーザーの了承を得て修正

## チェックリスト

### A. スタイル再現度（最重要）
- [ ] 一覧で見える最初の1行が、読者の違和感に触れているか
- [ ] 一人称が「わたし」か
- [ ] **太字**が十分に使われているか（各セクション最低1つ）
- [ ] 「笑」を使っていないか（わたしのスタイルではない）
- [ ] 語尾が単調でないか（「です」連続NG）
- [ ] 問いかけ → 即答えパターンがあるか
- [ ] 短文のリズムが保たれているか（一文60文字以内）
- [ ] 1行ごとの改行になっていないか（空白を空けすぎず、文章の内容を重視）
- [ ] P.S. / P.P.S. / P.P.P.S. を使っていないか

### B. 冒頭チェック
- [ ] 最初の3行で引き込めているか
- [ ] AI使用の開示を不要に入れていないか
- [ ] 「この記事では〜」的な退屈な始め方になっていないか

### C. コンテンツチェック
- [ ] 体験談・エピソードが含まれているか
- [ ] 具体例があるか（抽象論だけで終わっていないか）
- [ ] 数字・データが含まれているか（可能な場合）
- [ ] 読者に「考えさせる問い」が投げかけられているか

### D. 哲学チェック
- [ ] Well-being / LTR / Giver・Taker / 価値提供 のいずれかに着地しているか
- [ ] 必要な場合だけ、自分の事業や活動に自然に接続しているか
- [ ] 機械的な「スキ」「フォロー」CTAに頼っていないか
- [ ] 「最後まで読んでいただきありがとうございました」系の締め方になっていないか

### E. 構成チェック
- [ ] 記事タイプに合った構成になっているか
- [ ] 見出しだけ読んで内容が把握できるか
- [ ] 「で、ここからが本当に伝えたかったこと」的な転換点があるか
- [ ] 適切な長さか（文字数だけを目的化せず、深い記事は必要な長さになっているか）

### G. noteフォーマット互換チェック
- [ ] `###` 以下の見出しを使っていないか（noteは `#` と `##` の2段階のみ）
- [ ] テーブル（表）を使っていないか（noteエディタにはテーブル機能がない → 箇条書きに変換）
- [ ] コードブロックを使っていないか（noteにはコードブロックがない → 引用ブロックor本文に変換）
- [ ] noteに貼り付けた際の太字変換が意識されているか（`**text**` はnoteで反映されない）

### F. 入口チェック
- [ ] タイトル表示だけで、誰のどんな違和感かわかるか
- [ ] 最初の1行が、一覧から開く理由になっているか
- [ ] ハッシュタグ候補を考えたか
- [ ] サムネイル画像のイメージが浮かぶか

### H. note運用チェック
- [ ] 想定掲載カテゴリがあるか
- [ ] 掲載カテゴリに合うタグ・タイトル・本文内容になっているか
- [ ] サムネ文字は一覧で読める大きさか
- [ ] スキ数ではなく、初動インプレッション/PVと7日後PVで判断する前提になっているか
- [ ] 有料記事候補にするなら、無料では足りない深さや整理があるか
