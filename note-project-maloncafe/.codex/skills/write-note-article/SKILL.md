# スタイル note記事執筆

## 現行方針（2026-10-07）

このスキルでは、旧来の「note量産」「フォロワー獲得」より、現在の「違和感収集家」運用を優先する。

- 最終目的は、1本で深く整理できる違和感を見つけ、有料記事として成立するか探索すること。
- フォロワー獲得や交流を目的にしない。機械的な「スキ」「フォロー」CTAは必須にしない。
- スキ数を成果指標にしない。公開後は、掲載カテゴリ、初動インプレッション、初動PV、表示→PV率、7日後PV、回遊/有料記事PVを見る。
- 記事を書く心理的コストを考慮し、書く理由が弱いテーマは無理に記事化しない。
- ZODIAC/zodiacm369 側のビジネス系・量産系文体を混ぜない。
- 投稿前後の運用判断は `research/note-operation-checklist.md` を参照する。
- サムネ制作は `templates/note-thumbnail-prompt.md` を参照する。

## ワークフロー

### Step 1: コンテキスト読み込み（必須）
以下を**すべて**読む:
1. `config/author-profile.md` — わたしの文体・トーン
2. `config/company-philosophy.md` — 哲学
3. `config/writing-style-guide.md` — ライティングスタイルガイド
4. `research/note-operation-checklist.md` — 現行の投稿前後チェック
5. `research/` 配下の関連リサーチメモ（あれば）
   - 市場リサーチ（キーワード需要・競合・有料化判断）とトピックリサーチ（哲学接続）の両方を確認
   - 市場メモがなければ、執筆前に research-note-market の実行を提案してよい

### Step 2: テンプレート選択
旧テンプレートは参考扱い。現行運用では、まず「どの違和感を深く整理するか」と「入口でどう開かせるか」を決める。

| テンプレート | いつ使う |
|------------|---------|
| `experience-review.md` | 何かを試した体験を語るとき |
| `philosophy.md` | 根源的な問いに答えるとき |
| `company-story.md` | 会社の軌跡やビジョンを語るとき |
| `vision-product.md` | 新概念の提唱やプロダクト紹介のとき |

現行の優先判断:
- Xキーワードやリサーチから拾った違和感語を起点にする。
- タイトル表示と最初の1行で、誰のどんな違和感かを伝える。
- 有料記事候補にする場合は、無料では足りない深さ、問い、構造、チェックリストがあるかを見る。
- 広いPVが取れるテーマでも、違和感収集家本流とズレる場合は別系統として扱う。

### Step 3: 構成案をユーザーに確認
テンプレートをベースに見出し案を作り、確認を取る。

### Step 4: 執筆
以下のルールに従って執筆する。

### Step 5: 保存
`articles/drafts/YYYYMMDD-タイトル.md` で保存。

## 執筆ルール（スタイル）

### 冒頭（内容によって唐突に始まる場合もある）
- 一覧で見える最初の1行を優先する。あいさつを入れる場合も、読者が開く理由を弱めない位置・長さにする
- AI使用の開示はいれない
- 最初の1行で、読者が「自分の話かも」と思える場面を置く
- 最初の3行で「え、何それ？」と思わせるフックを入れる
- 「この記事では〜」的な退屈な始め方は**絶対禁止**

### 本文の文体
- 一人称は「わたし」
- カジュアル口語体ベース
- **太字を超多用**（各段落に最低1つ）
- 一文は短く（60文字以内）
- 1行ごとの改行はしない。文章の内容と論理の流れを優先し、段落単位で読ませる
- 空白を空けすぎない。スマホ最適化よりも、文章として刺さる密度を優先する
- 「笑」は使わない（わたしのスタイルではない）
- 問いかけ → 即答え のパターンを多用
- 体験談・エピソードを必ず入れる

### 語尾の注意
- 同じ語尾が3回連続しないようにする
- 「〜です。」「〜ます。」だけでなく、「〜なんですよね。」「〜でしょ？」「〜なわけです。」を混ぜる
- 断言するときは「〜です。断言します。」

### 太字の使い方
- 核心メッセージ: **その段落で一番言いたいこと**
- 転換点: **「でもね、ここに重要な前提がある。」**
- 独立した強調: 2〜3行を太字にして独立させる

### noteエディタのフォーマット制約（重要）
noteのエディタで使えるのは以下のみ:
- `#` 見出し / `##` 小見出し（`###`以下は**使えない**）
- `- ` `+ ` `* ` 箇条書きリスト
- `1. ` `2) ` 番号付きリスト
- `> ` `>> ` 引用ブロック
- 太字（エディタ上でテキスト選択 → B）
- `---` 区切り線

**使えないもの**: `###`以下の見出し、テーブル、コードブロック、Markdownの太字記法 `**text**`

下書きファイルでは `**太字**` や `###` を使ってOK（可読性のため）。
ただし**noteに貼り付ける際の変換**を意識して、テーブルは使わず箇条書きで代替する。

### 哲学への着地（必須）
- 記事の後半で必ず哲学に接続する
- Well-being / LTR / Giver・Taker / 価値提供 / バズる のいずれか
- 押しつけがましくなく、ストーリーの自然な帰結として

### 締め方
1. ひとつのきっかけになるようなものであればうれしいです
2. 機械的な「スキ」「フォロー」CTAは必須にしない
3. 読者交流を前提にしない。記事単体で完結させる
4. 署名: （なし）


## 品質チェック

記事が書けたら以下を確認:
- [ ] タイトル表示だけで、誰のどんな違和感かわかるか
- [ ] 最初の1行で、読者が自分の話だと思えるか
- [ ] 冒頭3行にフックがあるか
- [ ] 太字が十分に使われているか（各セクション最低1つ）
- [ ] 体験談・エピソードが含まれているか
- [ ] 哲学への着地があるか
- [ ] 文字数だけを目的化していないか
- [ ] 有料記事候補として深く整理できる違和感があるか
